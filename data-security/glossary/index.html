Glossary

Short definitions of the streaming, distributed systems, data platform, security and regulatory terms used across the handbook, with links to the articles that explain them.

  • 4 min read
  • Reviewed November 1, 2026
  • #Reference

Definitions are deliberately short. Follow the links for the full explanations.

A–C#

ABAC (attribute-based access control)
Access decisions from attributes of the user, the data and the context. See Data security.
At-least-once delivery
Messages are never lost but may be duplicated. See Producers and consumers.
BCBS 239
Basel principles for risk data aggregation and reporting. See Data governance.
BOLA
Broken object-level authorisation, the top API security risk. See Security architecture.
CAP theorem
Under a network partition, choose consistency or availability. See Consistency.
CDC (change data capture)
Streaming database changes from the transaction log. See Outbox and CDC.
CDE (cardholder data environment)
Systems that store, process or transmit card data, and so fall in PCI DSS scope. See FinTech regulations.
Compensating transaction
A business action that semantically undoes an earlier saga step. See Saga.
Consumer group
Kafka consumers sharing partitions, one owner per partition. See Kafka architecture.
CQRS
Separate models for commands (writes) and queries (reads). See CQRS and event sourcing.
Crypto-shredding
Making data unreadable by deleting its encryption key. See Data security.

D–I#

Data contract
A producer–consumer agreement covering schema, semantics, quality, SLOs and ownership. See Schemas and contracts.
Data mesh
Domain-owned data products on a self-serve platform with federated governance. See Data platforms.
DORA
The EU Digital Operational Resilience Act for financial entities, applicable since January 2025. See FinTech regulations.
DPDP Act
India’s Digital Personal Data Protection Act 2023, with Rules notified in 2025. See FinTech regulations.
Envelope encryption
Data encrypted with a data key, and the data key encrypted with a master key in a KMS or HSM. See Data security.
Event sourcing
Storing state as an append-only sequence of events. See CQRS and event sourcing.
Excessive agency
An AI system with more tools, permissions or autonomy than it needs. See AI security.
FAPI 2.0
OpenID Foundation security profile for financial-grade APIs. See Security architecture.
Iceberg
An open table format adding ACID, schema evolution and time travel to files. See Data platforms.
Idempotency
An operation that has the same effect whether applied once or many times. See Outbox and idempotency.
ISR (in-sync replicas)
Kafka replicas caught up with the partition leader. See Kafka architecture.

K–P#

KRaft
Kafka’s built-in Raft metadata quorum, replacing ZooKeeper since 4.0. See Kafka architecture.
Lakehouse
Open table formats on object storage, queried by many engines under one catalog. See Data platforms.
Lineage
The record of where data came from and how it was transformed. See Data governance.
LINDDUN
A privacy threat-modelling method. See Threat modelling.
Linearizability
The strongest single-object consistency: behaves like one copy in real-time order. See Consistency.
Medallion architecture
Bronze (raw), silver (conformed) and gold (product) data layers. See Data platforms.
MITRE ATLAS
A knowledge base of adversarial techniques against AI systems. See AI security.
Outbox pattern
Writing state and event in one local transaction, and relaying the event later. See Outbox.
PACELC
Partition: availability or consistency; else: latency or consistency. See Consistency.
PCI DSS
The security standard for cardholder data; v4.0.1 is current. See FinTech regulations.
Post-quantum cryptography (PQC)
Algorithms resistant to quantum attacks (ML-KEM, ML-DSA, SLH-DSA). See Security architecture.
Prompt injection
Instructions in input or content that manipulate an LLM. See AI security.

R–Z#

Raft
A consensus protocol using leader election and majority log replication. See Consistency.
Saga
A sequence of local transactions with compensations. See Saga.
SBOM
A software bill of materials: an inventory of components. See Security architecture.
SCA (strong customer authentication)
Two of knowledge, possession and inherence, required by PSD2. See FinTech regulations.
Schema registry
A service that stores schema versions and enforces compatibility. See Schemas and contracts.
Share group
Queue-style Kafka consumption with per-record acknowledgement (KIP-932). See Kafka architecture.
SLSA
Supply-chain Levels for Software Artifacts: build integrity and provenance. See Security architecture.
STRIDE
Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege. See Threat modelling.
TCC (Try–Confirm–Cancel)
Reserve resources, then confirm or cancel them. See Distributed transactions.
Tokenisation
Replacing sensitive values with random tokens mapped in a secure vault. See Data security.
Watermark
A stream processor’s estimate of event-time progress, used to close windows. See Stream processing.
Zero trust
No implicit trust from network location; verify every request. See Security architecture.
