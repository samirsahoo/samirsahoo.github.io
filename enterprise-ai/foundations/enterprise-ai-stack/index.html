The Enterprise AI Stack: Reference Architecture

The layers of an enterprise AI platform — infrastructure, models, AI gateway, data and knowledge, orchestration and agents, applications, LLMOps, security and governance — with a reference architecture, request flow and platform-team operating model.

Simple definition#

The enterprise AI stack is the set of shared layers an organisation builds so that many teams can ship AI features safely and cheaply: access to models, a gateway to control that access, pipelines that turn company data into retrievable knowledge, frameworks for chains and agents, and the operations, security and governance around all of it.

The problem it solves#

Without a platform, every team picks its own model, stores its own API keys, builds its own vector store, logs prompts (with customer data) in different places, and nobody knows the total cost or which apps send personal data to which vendor. That is “shadow AI”: fast at first, ungovernable at scale.

The layered architecture#

Layer Responsibility Typical technologies
1–2 Infrastructure Compute, GPUs, networking, storage Kubernetes, GPU node pools, vLLM/TGI, object storage
3 Models Generation, embeddings, reranking, speech/vision Provider APIs, AWS Bedrock, Azure AI Foundry, Google Vertex AI, open-weight models
4 AI gateway Single controlled entry point to all models LiteLLM, Kong AI Gateway, Azure APIM, Envoy AI Gateway, Portkey, Cloudflare AI Gateway
5 Knowledge Turn enterprise data into context ETL, Apache Tika/parsers, pgvector, OpenSearch, Elasticsearch, Pinecone, Neo4j
6 Orchestration Chains, RAG flows, agents, tool access Spring AI, LangChain/LangGraph, LlamaIndex, Semantic Kernel, MCP servers
7 Experiences What users touch Web/mobile apps, chat in Teams/Slack, IDE plugins, back-office automations
Cross-cutting: LLMOps Traces, evals, prompt versions, cost OpenTelemetry, Langfuse, LangSmith, Arize Phoenix, MLflow
Cross-cutting: Governance Policy, risk, audit, compliance AI inventory, model cards, DLP, IAM, policy engines

AI gateway#

The AI gateway (LLM gateway) is the most important platform component for control. Every model call in the company goes through it.

Benefits: one place for provider keys and contracts, central cost visibility and chargeback, consistent safety policies, provider failover, and a single audit trail.

A request flowing through the stack#

Build vs buy at each layer#

Layer Usually buy / use managed Usually build
Models Yes (APIs, cloud-managed) Fine-tuned adapters for narrow tasks
Gateway Product or open source, configured centrally Custom policies, chargeback integration
Vector store Managed DB or extension (pgvector, OpenSearch) —
Ingestion pipelines Connectors where available Parsing, chunking and metadata for your documents
Orchestration Framework (Spring AI, LangGraph) Business workflows, tools, prompts
Evaluation Tooling Golden datasets and domain metrics — only you can build these

Operating model: the AI platform team#

The platform team provides paved roads; product teams own use cases, prompts, evaluation sets and outcomes. A governance board (risk, legal, security, data protection) approves use cases by risk tier. See AI governance.

Use-case prioritisation#

A strategic AI architect also decides what to build. Score candidate use cases on:

  • Value — revenue, cost saving, risk reduction, customer experience.
  • Feasibility — data availability and quality, task suits current models, integration effort.
  • Risk — regulatory tier, harm if wrong, need for human oversight.

Start with high-value, high-feasibility, lower-risk internal use cases (knowledge assistants, document processing, developer productivity), build the platform through them, then move to customer-facing and agentic use cases.

Common mistakes#

Common mistakeBuilding the platform before any use case

A platform designed in the abstract builds the wrong things. Build it through the first two or three real use cases and extract the shared parts.

Common mistakeApps calling providers directly with shared keys

No cost attribution, no consistent guardrails, no audit, and a key leak affects everyone. Route everything through the gateway with per-app credentials.

Common mistakeTreating the vector store as the knowledge layer

The hard part is ingestion: parsing PDFs and tables, chunking, metadata, permissions and freshness. Budget most RAG effort there.

Review questions#

Describe an enterprise AI reference architecture. Infrastructure and models at the bottom (provider APIs, cloud-managed and self-hosted models, embeddings and rerankers); an AI gateway as the single controlled entry point; a knowledge layer for ingestion, vector and hybrid search and knowledge graphs; an orchestration layer for chains, RAG and agents with a tool/MCP registry; applications on top; and cross-cutting LLMOps (tracing, evaluation, cost) and governance (identity, data protection, policy, audit).

What does an AI gateway do and why do you need one? Authenticates apps, enforces quotas, applies input and output guardrails, caches, routes to models with fallback, and logs and meters every call for cost and audit. It centralises control, security and cost visibility and avoids lock-in.

How do you organise teams for enterprise AI? A central platform team builds paved roads (gateway, RAG components, eval tooling, guardrails), a governance board sets policy and reviews risk, and product teams own use cases, prompts, evaluation data and outcomes.

How do you decide which AI use cases to do first? Score on value, feasibility (data, model fit, integration) and risk. Start with internal, high-value, lower-risk use cases to build the platform and capability, then expand.

Review tipDraw the layers, then trace a request

In a design review, draw the stack quickly, then walk one request through it end to end — identity, retrieval with access filters, gateway, model, guardrails, response, tracing. That shows you understand how the parts interact, not just their names.

Summary#

  • The stack: infrastructure → models → AI gateway → knowledge → orchestration/agents → experiences, with LLMOps and governance across all layers.
  • The AI gateway is the control point for cost, security, routing and audit.
  • Buy commodity layers; build ingestion, business logic and evaluation data.
  • A platform team with governance and product teams on top scales AI safely.
