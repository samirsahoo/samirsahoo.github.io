Claude Code for Teams and Organisations

Rolling Claude Code out beyond one developer: what to commit to the repo, settings precedence, managed settings and what admins can enforce, API providers and gateways, plugin marketplaces, cost benchmarks and spend controls, analytics and OpenTelemetry, data handling, and a phased rollout plan.

Simple definition#

For a team, Claude Code configuration has three owners. The repository carries shared conventions, permissions, hooks, skills, agents and MCP servers, committed like any other code. Each developer keeps personal preferences in local and user files. The organisation sets policy through managed settings that no one else can override, and watches usage and spend through analytics and telemetry.

Version noteSource and date

From Anthropic’s Set up Claude Code for your organization, Settings, Costs, Analytics, Monitoring usage and Plugin marketplaces, read on 7 November 2026.

What to commit to the repository#

Path Purpose Notes
CLAUDE.md Commands, misleading code, decisions not in the repo Under 200 lines; CLAUDE.local.md for personal notes (gitignored)
.claude/rules/*.md Path-scoped rules (paths: frontmatter) Load only when matching files are touched
.claude/settings.json Permissions, hooks, env, enabled plugins, marketplaces deny/ask apply at once; allow, hooks, marketplaces and most env wait for each developer’s workspace trust
.claude/skills/ Team procedures: release, incident runbook, API docs style disable-model-invocation: true for anything with side effects
.claude/agents/ Shared sub-agents (a read-only reviewer, a test writer) Restrict tools; use model: haiku for simple jobs
.mcp.json Team MCP servers Each developer approves project servers; keep secrets in env vars
.worktreeinclude Gitignored files new worktrees need Small files only

TipBootstrap a teammate

/team-onboarding turns your last 30 days of sessions, commands and MCP usage into a guide a new teammate can paste as their first message. /insights shows how you use Claude Code and where it goes wrong.

Settings precedence#

Highest first — a key set higher overrides the same key lower down:

  1. Managed settings — server-delivered, MDM/registry, or managed-settings.json. Nothing below can override them.
  2. Command line — --settings <file|json> for one session.
  3. Project local — .claude/settings.local.json (yours, gitignored).
  4. Shared project — .claude/settings.json (committed).
  5. User — ~/.claude/settings.json.
  • Arrays merge across scopes. permissions.allow and permissions.deny collect entries from every level, so developers can add to managed lists but not remove from them.
  • Permission rules combine by kind, not only by level: a local allow doesn’t outrank a project or managed ask. Deny always wins.
  • A few restrictive keys (for example blockWritesOutsideWorkingDirectories: true) are honoured from any scope even if managed settings say otherwise.
  • /status shows which sources are active (Setting sources).

Managed settings: delivery#

Mechanism Where Priority
Server-managed Claude admin console (Team/Enterprise), or a self-hosted Claude apps gateway Highest; fetched at start, refreshed hourly
OS policy macOS plist com.anthropic.claudecode; Windows HKLM\SOFTWARE\Policies\ClaudeCode High; admin-only, tamper-resistant
File /Library/Application Support/ClaudeCode/, /etc/claude-code/, C:\Program Files\ClaudeCode\ → managed-settings.json Medium
Windows user registry HKCU\SOFTWARE\Policies\ClaudeCode Lowest; a convenience default, not enforcement

WSL reads only the Linux path unless wslInheritsWindowsSettings: true is set in an admin-only Windows source. Mixed providers: server-managed for claude.ai users plus a file or OS-policy fallback for everyone else.

Managed settings: what admins can enforce#

Control Keys
Permission rules, and make managed the only source permissions.allow/deny, allowManagedPermissionRulesOnly
Ban --dangerously-skip-permissions; remove auto mode; set starting mode permissions.disableBypassPermissionsMode, permissions.disableAutoMode, permissions.defaultMode
OS sandbox with a network allowlist sandbox.enabled, sandbox.network.allowedDomains
MCP servers allowed, denied or provided allowedMcpServers, deniedMcpServers, allowManagedMcpServersOnly, managedMcpServers
Plugin and marketplace sources strictKnownMarketplaces, blockedMarketplaces, disableSideloadFlags
Customisations only from plugins or policy strictPluginOnlyCustomization
Hooks allowManagedHooksOnly, allowedHttpHookUrls
Login method, organisation and provider login enforcement keys, allowedProviders
Models and effort availableModels, enforceAvailableModels, maxEffortLevel
Versions minimumVersion, requiredMinimumVersion, requiredMaximumVersion
Background agents disableAgentView, or processWrapper for a corporate launcher
Telemetry to Anthropic off env.CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
Organisation-wide guidance Managed-policy CLAUDE.md (advice, not enforcement) 
{
  "permissions": {
    "deny": ["Read(./.env)", "Read(./.env.*)", "Read(**/secrets/**)", "Bash(curl * | bash)"],
    "disableBypassPermissionsMode": "disable"
  },
  "sandbox": { "enabled": true, "network": { "allowedDomains": ["github.com", "*.internal.example.com"] } },
  "maxEffortLevel": "xhigh",
  "minimumVersion": "2.1.300"
}

WarningPermissions and sandbox are different layers

Denying WebFetch blocks Claude’s fetch tool, but if Bash is allowed, curl can still reach any URL. Only the sandbox’s domain allowlist enforces network limits at the OS level. Use both.

Choosing a provider#

Provider Choose when Watch out
Claude for Teams / Enterprise Default: one per-seat subscription for Claude Code and claude.ai, nothing to run —
Claude Console (API) API-first, pay-as-you-go No cloud sessions, scheduled cloud tasks, Code Review, Remote Control or Chrome without a claude.ai login
Amazon Bedrock / Google Cloud Agent Platform / Microsoft Foundry Inherit existing cloud compliance and billing Same feature gaps; org model and effort controls on claude.ai don’t apply — use availableModels, model, maxEffortLevel in managed settings
LLM gateway / Claude apps gateway One endpoint, SSO, per-request audit log, per-user spend limits Gateway sessions aren’t eligible for the HIPAA configuration

Proxies, custom CAs and mTLS: see enterprise network configuration.

Sharing extensions with plugins#

A plugin bundles skills, sub-agents, hooks and MCP servers; a marketplace is a catalogue of plugins (often a Git repository). Teams publish an internal marketplace and declare it in .claude/settings.json (extraKnownMarketplaces, enabledPlugins), so a clone plus workspace trust installs the team’s tooling. Admins restrict sources with strictKnownMarketplaces and can install shared plugins on every machine through managed settings. Review a plugin before trusting it — it runs code on the developer’s machine. /skill-doctor shows each skill’s context cost and use, so unused ones can be retired.

Cost: benchmarks and controls#

Key conceptThe benchmark

Across enterprise deployments Anthropic reports an average of about $13 per developer per active day and $150–250 per developer per month, with 90% of users below $30 per active day. Start with a pilot and measure your own.

Lever How
Biggest habits /clear between unrelated tasks; match the model to the job (Sonnet for routine work)
Context overhead Disable unused MCP servers; move long CLAUDE.md sections into skills; code-intelligence plugins instead of grep-and-read
Effort Lower for simple work; cap with maxEffortLevel
Parallelism Sub-agents, agent teams and /loop all multiply requests — model: haiku, short summaries
Hard limits Organisation spend limits (Team/Enterprise), workspace limits (Console), cloud budgets, gateway per-user limits; --max-budget-usd in scripts
Per-developer view /usage breaks usage down by skill, sub-agent, plugin and MCP server

export OTEL_METRICS_EXPORTER=otlp

Put these in managed settings’ env so every machine reports. Measure outcomes (lead time, change failure rate, review load) alongside usage — see Using Claude intelligently.

Data handling#

  • On Team, Enterprise, API and cloud-provider plans, Anthropic does not train on your code or prompts; your provider determines retention.
  • Zero data retention is available to qualified Enterprise accounts; a HIPAA configuration exists for Enterprise organisations that have it enabled (some features off).
  • For request-level audit logging or routing by data sensitivity, put a gateway in front of the provider.
  • Code Review, cloud sessions and cloud scheduled tasks run on Anthropic infrastructure — include them in your data classification decisions.

A phased rollout#

Phase Do Exit criterion
1. Pilot (2–4 weeks) 10–20 volunteers across stacks; managed deny rules for secrets; OTel on Measured cost per active day; top three friction points known
2. Team baseline Commit CLAUDE.md, .claude/settings.json, a reviewer agent and a release skill to key repos; internal marketplace New joiner productive from a clone
3. Guardrails Sandbox, disableBypassPermissionsMode, MCP allowlist, version floor, spend limits; branch protection everywhere Policy visible in /status on every machine
4. Automation GitHub Actions / Code Review on PRs; /schedule for triage; claude -p jobs with caps Automated PRs merged only after human review
5. Scale and measure Seats for everyone; analytics review monthly; prune unused skills and MCP servers Delivery metrics improve without rising change failure rate

Anthropic’s communications kit has launch announcements and FAQ copy; developers can start with the Quickstart and Common workflows.

Common mistakes#

Common mistakePolicy in CLAUDE.md

A managed CLAUDE.md is guidance the model weighs. Security policy belongs in managed permission rules, the sandbox and hook restrictions.

Common mistakeRelying on the Windows user registry

HKCU is writable without elevation. Use HKLM, plist, the file path or server-managed settings for anything you must enforce.

Common mistakeChoosing a cloud provider without checking features

Bedrock, Agent Platform and Foundry credentials alone don’t unlock cloud sessions, Code Review or Remote Control. Decide whether developers also need Team or Enterprise seats.

Common mistakeMeasuring adoption instead of outcomes

Lines accepted and active users show usage, not value. Pair them with lead time, defect and review metrics.

Review questions#

A developer adds an allow rule locally for a command that the organisation lists under deny. What happens? The command is denied. Permission arrays merge across scopes and deny wins; developers can add to managed lists but not remove from them.

Your organisation uses Amazon Bedrock. How do you cap effort and restrict models? With managed settings — availableModels (plus enforceAvailableModels), model for a default, and maxEffortLevel — because claude.ai organisation model controls don’t reach Bedrock sessions.

What is a reasonable starting budget per developer? About $150–250 a month on average (around $13 per active day), but measure your own in a pilot before committing.

Summary#

  • Commit the team’s Claude Code setup like code; keep personal preferences in local files.
  • Managed settings sit at the top of precedence and merge arrays, so policy can’t be removed locally.
  • Enforce with permissions and the sandbox; restrict MCP, plugins, hooks, models, effort and versions centrally.
  • Pick a provider knowing its feature gaps; add a gateway for audit and per-user limits.
  • Pilot, measure cost and outcomes with analytics and OpenTelemetry, then scale in phases.
