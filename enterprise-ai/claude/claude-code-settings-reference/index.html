Simple definition#

Claude Code reads JSON settings files at several levels — your user file, the project’s shared and local files, and the organisation’s managed settings — and combines them into one effective configuration. Settings control what Claude may do (permissions, sandbox), which model it uses, what loads into context, which extensions run, and what is reported. Environment variables cover authentication, providers and a few low-level limits.

Version noteSource and date

Condensed from Anthropic’s Settings, All settings (about 250 keys), Configure permissions and Environment variables, read on 7 November 2026. This page covers the keys you are most likely to set; look up anything else in the official index.

Files#

File Who Committed Typical contents
~/.claude/settings.json You, every project No Model, effort, theme, status line, autoMode, personal hooks
.claude/settings.json Everyone in the repo Yes Permissions, hooks, env, plugins, marketplaces
.claude/settings.local.json You, this repo No (gitignored) Personal overrides; “don’t ask again” approvals land here
Managed settings Organisation Deployed Policy: deny rules, sandbox, MCP and plugin limits, versions
--settings <file|json> One session — Script and CI overrides
~/.claude.json You No Global config (IDE, UI toggles), local-scope MCP servers, per-project state
.mcp.json Repo Yes Project MCP servers

Edit with /config (UI or key=value), /permissions, /hooks, or ask Claude via /update-config. Add "$schema": "https://json.schemastore.org/claude-code-settings.json" for editor completion. /status shows which sources loaded.

Precedence and merging#

Highest first: managed → command line (--settings) → project local → shared project → user. A key set higher overrides the same key lower down — but not every key merges the same way:

Kind of key Rule Examples
Arrays Merge across all scopes — lower levels can add, not remove permissions.allow, permissions.deny, sandbox.network.allowedDomains
Locks The strictest value any source sets wins allowManagedPermissionRulesOnly, permissions.disableBypassPermissionsMode
Restrictive booleans A restrictive true from any scope is honoured, even over managed permissions.blockWritesOutsideWorkingDirectories, disableClaudeAiConnectors
Managed-replace lists The managed value replaces lower ones availableModels, fallbackModel, modelPicker
Highest source only Read only from the top source with policy apiKeyHelper, permissions.defaultMode
Everything else Highest level that sets it model, cleanupPeriodDays
  • Project allow rules, additionalDirectories, marketplaces and most env values wait for workspace trust; deny and ask apply immediately.
  • Shell environment variables are not a level: some (ANTHROPIC_MODEL) beat the matching settings key, others don’t — check the key’s entry.
  • CLAUDE.md edits don’t apply mid-session, because the system prompt is cached; start a new session to pick them up.

Permission rule syntax#

Rules are Tool or Tool(specifier) in permissions.allow, ask or deny. Deny beats ask beats allow, in every mode.

Rule Matches
Bash Every shell command
Bash(npm run build) Exactly that command
Bash(npm run *) npm run build, npm run test --watch (not npm install)
Bash(git * main) git merge main, git push origin main
Bash(ls *) vs Bash(ls*) ls -la / also lsof — the space matters
Read(./.env), Read(**/.env) .env here / any .env under the working directory
Read(~/Documents/*.pdf) Path from home
Read(//etc/**) Absolute path from filesystem root
Edit(/src/**/*.ts) Relative to the settings file’s project root
Edit(**/src/**) A src directory at any depth
WebFetch(domain:example.com) Fetches to that domain
mcp__github, mcp__github__* Every tool from the github server
mcp__github__create_issue One MCP tool
Agent(Explore), Agent(my-reviewer) A sub-agent (deny to disable it)
Agent(model:opus), Bash(run_in_background:true) Calls with that input parameter

WarningBash patterns are not a sandbox

Bash(curl *) doesn’t match /usr/bin/curl … or sh -c 'curl …'; a Read deny doesn’t stop a script that opens the file; a WebFetch deny doesn’t stop curl. Use the sandbox for real filesystem and network limits.

Key Does
permissions.allow / ask / deny Rule lists
permissions.defaultMode Starting mode: default, acceptEdits, plan, auto, dontAsk, bypassPermissions

permissions.disableBypassPermissionsMode "disable" — nobody can enter bypass mode

Put shared variables in a settings file’s env block rather than shell profiles, so every session and subprocess gets them.

Example: a developer’s user settings#

{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "opus",
  "effortLevel": "medium",
  "theme": "auto",
  "statusLine": { "type": "command", "command": "~/.claude/statusline.sh" },
  "autoMode": {
    "environment": ["$defaults", "Source control: github.com/example-org", "Trusted internal domains: *.internal.example.com"],
    "allow": ["$defaults", "Deploying to the staging namespace is fine; it resets nightly"]
  }
}

Example: a team’s .claude/settings.json#

{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": ["Bash(./mvnw *)", "Bash(git diff *)", "Bash(gh pr view *)"],
    "ask":   ["Bash(git push *)"],
    "deny":  ["Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)", "Edit(/src/gen/**)"]
  },
  "env": { "SPRING_PROFILES_ACTIVE": "local" },
  "hooks": {
    "PostToolUse": [{ "matcher": "Edit|Write",
      "hooks": [{ "type": "command", "command": "./mvnw -q spotless:apply" }] }],
    "Stop": [{ "hooks": [{ "type": "command", "command": "./mvnw -q -DskipITs test 1>&2 || exit 2" }] }]
  },
  "extraKnownMarketplaces": {
    "acme-tools": { "source": { "source": "github", "repo": "acme/claude-plugins" } }
  },
  "enabledPlugins": { "acme-reviewer@acme-tools": true },
  "attribution": { "commit": "Co-Authored-By: Claude <noreply@anthropic.com>" }
}

Example: organisation managed settings#

{
  "permissions": {
    "deny": ["Read(**/.env)", "Read(**/secrets/**)", "Read(~/.aws/**)", "Bash(curl * | bash)"],
    "disableBypassPermissionsMode": "disable"
  },
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "network": { "allowedDomains": ["github.com", "*.npmjs.org", "*.internal.example.com"] }
  },
  "allowManagedMcpServersOnly": true,
  "strictKnownMarketplaces": [{ "source": "github", "repo": "acme/claude-plugins" }],
  "maxEffortLevel": "xhigh",
  "minimumVersion": "2.1.300",
  "env": {
    "CLAUDE_CODE_ENABLE_TELEMETRY": "1",
    "OTEL_METRICS_EXPORTER": "otlp",
    "OTEL_EXPORTER_OTLP_ENDPOINT": "https://otel.internal.example.com:4317"
  }
}

Structured keys such as strictKnownMarketplaces accept more source types (git, url, host patterns) — see the reference before deploying.

Common mistakes#

Common mistakeautoMode in project settings

The classifier ignores autoMode in project files, and omitting "$defaults" replaces the built-in rules — including the blocks on force pushes and production deploys.

Common mistakeExpecting a local allow to beat a project ask

Permission rules combine by kind: deny beats ask beats allow across all files. “Yes, and don’t ask again” saves an allow to your local file, which won’t silence a team ask rule.

Common mistakeANTHROPIC_API_KEY left in a shell profile

It silently overrides your subscription login and bills the API key. Set it only where you mean to.

Common mistakeSecrets in committed env

.claude/settings.json is in Git. Use apiKeyHelper, your secret manager, or settings.local.json.

Review questions#

The organisation denies Read(**/.env); a developer adds Read(./.env) to their local allow list. Can Claude read .env? No. Arrays merge across scopes and deny wins over allow.

Where must autoMode customisation go, and why keep "$defaults"? In ~/.claude/settings.json (user settings); without "$defaults" your entries replace the built-in list rather than extend it.

Which keys are honoured from any scope even if managed settings disagree? Restrictive ones such as permissions.blockWritesOutsideWorkingDirectories: true and disableClaudeAiConnectors: true — a developer can always make their own session stricter.
