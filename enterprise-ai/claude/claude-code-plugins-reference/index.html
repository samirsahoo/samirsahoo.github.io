Claude Code Plugins Reference

Packaging and sharing Claude Code extensions as plugins: what a plugin contains, directory layout and components, the plugin.json manifest, namespacing, install scopes, marketplaces and marketplace.json, /plugin and claude plugin commands, developing with --plugin-dir, evals and cost, security and trust, and organisation controls.

Simple definition#

A plugin is a directory that bundles Claude Code extensions — skills, sub-agents, hooks, MCP servers, language servers, output styles and more — so they install, update and enable as one unit. A marketplace is a catalogue (usually a Git repository with a marketplace.json) that lists plugins and where to fetch them. Plugins are how a team or organisation shares one Claude Code setup across many repositories and machines.

Version noteSource and date

Condensed from Anthropic’s Plugins overview, Plugin components, Manifest reference, Plugin marketplaces and Plugin CLI reference, read on 7 November 2026.

Do you need a plugin?#

You want… Use
One skill, agent, hook or server for yourself or one repo The standalone file (.claude/skills/, .claude/agents/, settings, .mcp.json)
The same setup in many repos, or for a whole team A plugin in a marketplace
Someone else’s tooling with one command and updates Install their plugin
Policy that users can’t remove Managed settings (which can force-install plugins)

Directory layout#

my-plugin/
├── .claude-plugin/
│   └── plugin.json        # manifest (only "name" is required; optional altogether)
├── skills/
│   └── review/SKILL.md    # → /my-plugin:review
├── commands/about.md      # older single-file commands
├── agents/security-reviewer.md
├── hooks/hooks.json       # same format as settings "hooks"
├── .mcp.json              # MCP servers started while enabled
├── .lsp.json              # language servers (code intelligence)
├── monitors/monitors.json # background commands whose output reaches Claude
├── output-styles/terse.md
├── themes/dracula.json
├── workflows/             # dynamic workflow scripts
├── scripts/format.sh      # called by hooks via ${CLAUDE_PLUGIN_ROOT}
└── evals/                 # cases for claude plugin eval
Component Appears as
Skill / command /my-plugin:name
Agent my-plugin:security-reviewer
Hook Runs at its event while enabled
MCP server mcp__plugin_my-plugin_<server>__<tool>
LSP server Go-to-definition and diagnostics for its language
Output style /output-style my-plugin:terse
Theme In /theme
Monitor Notifications from a background command
Hooks module (JavaScript) A mod — can also draw panes and add commands

Every component is namespaced under the plugin name, so two plugins can both have a review skill.

plugin.json#

{
  "name": "acme-dev",
  "displayName": "Acme developer toolkit",
  "version": "1.4.0",
  "description": "Review, release and database tools for Acme services",
  "author": { "name": "Platform Team", "email": "platform@acme.example" },
  "license": "MIT",
  "keywords": ["review", "release"],
  "dependencies": ["acme-security"],
  "userConfig": {
    "webhook_url": { "type": "string", "title": "Slack webhook", "description": "Team channel webhook", "sensitive": true }
  }
}
Field Notes
name Required; kebab-case; the namespace for every component
version Pins users to that version until you change it
description, displayName, author, homepage, repository, license, keywords Metadata (homepage must be a valid URL)
defaultEnabled Start enabled unless the user says otherwise (default true)
dependencies Other plugins that must be enabled
userConfig Values Claude Code prompts for at enable time (available to hooks and servers as CLAUDE_PLUGIN_OPTION_*)
settings Settings applied while enabled — only agent and subagentStatusLine take effect
skills, commands, agents, hooks, mcpServers, lspServers, outputStyles, workflows Custom paths or inline config; most replace the default folder scan (skills adds to it; hooks and mcpServers load alongside the defaults)
experimental.themes, .monitors, .evals Shapes may change

Use ${CLAUDE_PLUGIN_ROOT} for paths inside the plugin and ${CLAUDE_PLUGIN_DATA} for persistent data.

Installing and managing#

In a session: /plugin opens Discover, Installed and Marketplaces tabs. /reload-plugins applies changes without restarting.

/plugin marketplace add acme/claude-plugins          # GitHub repo, git URL, local path or URL
/plugin install acme-dev@acme-tools

From the shell:

claude plugin install acme-dev@acme-tools --scope project
claude plugin enable|disable|uninstall acme-dev
claude plugin update acme-dev@acme-tools
claude plugin list · claude plugin details acme-dev
claude plugin configure acme-dev@acme-tools          # set userConfig values
claude plugin marketplace list|add|remove
claude plugin prune --dry-run                        # remove unused installs
Install scope Enabled for Recorded in
user You, every project ~/.claude/settings.json
project Everyone in the repo (each still installs locally) .claude/settings.json
local You, this repo .claude/settings.local.json

Anthropic’s official marketplace is added automatically on first interactive start (unless policy blocks it). Cloud sessions don’t load plugins from your local settings.

Creating a marketplace#

{
  "name": "acme-tools",
  "description": "Acme's internal Claude Code plugins",
  "owner": { "name": "Platform Team" },
  "plugins": [
    { "name": "acme-dev", "source": "./plugins/acme-dev", "description": "Review and release tools" },
    { "name": "acme-security", "source": { "source": "github", "repo": "acme/security-plugin" } }
  ]
}

Save as .claude-plugin/marketplace.json at the repository root. Then make it automatic for a repo:

{
  "extraKnownMarketplaces": {
    "acme-tools": { "source": { "source": "github", "repo": "acme/claude-plugins" } }
  },
  "enabledPlugins": { "acme-dev@acme-tools": true }
}

Committed in .claude/settings.json, this offers the marketplace and plugin to each developer once they trust the folder.

Developing a plugin#

claude plugin init acme-dev --with skills hooks   # scaffold
claude --plugin-dir ./acme-dev                    # load for one session, no marketplace
claude plugin validate .                          # check manifest and components
claude plugin eval                                # run eval cases with and without the plugin
claude plugin tag plugins/acme-dev --dry-run      # version tagging for releases
  • /reload-plugins picks up edits in a running session.
  • claude plugin eval measures whether skills and agents trigger on realistic prompts and improve results.
  • /skill-doctor and /usage show context cost and usage after release; the Installed tab groups plugins Not used recently.

What an enabled plugin costs#

  • Context: each model-invocable skill, agent and command adds its name and description to every turn.
  • Processes: its MCP servers and monitors run alongside every session; its hooks fire at their events.
  • Permissions: everything it runs, runs as you.

Disable plugins you aren’t using rather than leaving them on.

Security and trust#

  • Anthropic’s names (claude-plugins-official, claude-code-plugins, community names) are accepted only from github.com/anthropics/ repositories; every other marketplace is third-party.
  • Before installing: read the manifest, hooks, MCP server commands and any scripts. A plugin is code with your privileges.
  • Plugin MCP servers can’t read credential variables through ${VAR} expansion in remote URLs and headers.
  • Prefer pinned versions and a marketplace your organisation controls.

Organisation controls#

Setting Effect
strictKnownMarketplaces Allowlist of marketplace sources users may add
blockedMarketplaces Block specific sources
enabledPlugins (managed) Force-install and enable plugins on every machine
disableSideloadFlags Reject --plugin-dir, --plugin-url and similar one-session loading
disableCommandPluginSources Block plugins that install by running a command
strictPluginOnlyCustomization Skills, agents, hooks, MCP only from plugins or policy
pluginSuggestionMarketplaces Which marketplaces can suggest plugins
syncClaudeAiPlugins Stop loading plugins enabled on claude.ai

Common mistakes#

Common mistakeCopy-pasting .claude/ between repos

Copies drift. Package the shared setup as a plugin in an internal marketplace and enable it per repo.

Common mistakeOne giant plugin

Every enabled skill and agent costs context. Split by audience (backend, data, security) so teams enable only what they use.

Common mistakeUnpinned third-party plugins

An update can change hooks that run on your machine. Pin versions and review changes, or mirror into your own marketplace.

Review questions#

How is a plugin’s skill named once installed? /plugin-name:skill-name — every component is namespaced under the plugin’s name.

How do you make every developer in a repo get your team’s plugin? Declare the marketplace in extraKnownMarketplaces and the plugin in enabledPlugins in the committed .claude/settings.json.

How do you test a plugin without publishing it? claude --plugin-dir ./my-plugin, plus claude plugin validate . and claude plugin eval.
