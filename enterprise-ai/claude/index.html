Claude for Engineering & the SDLC

Using Anthropic's Claude across the software lifecycle: the model family and how to pick a model and effort level, the Claude API for builders, Claude Code for development, a phase-by-phase SDLC playbook, and the practices that make it safe, cheap and effective.

Modules 1–5 are vendor-neutral. This module goes deep on one model family — Anthropic’s Claude — because most engineering organisations now use it in two ways at once: as a model inside their products (through the Claude API or a cloud provider) and as an engineering tool that helps build those products (Claude Code, Claude apps, agents in CI). Both uses need the same skills: choosing the right model, giving it the right context, verifying what it produces, and controlling cost and risk.

Key conceptThe one idea to keep

Claude is most useful when you treat it as a fast, capable colleague who has no memory of your system and no stake in being right. Give it the context a new senior hire would need, a way to check its own work (tests, linters, evals), and a reviewer for anything that ships. Choose the smallest model and lowest effort that passes your checks, not the biggest one available.

Version noteReviewed 6 November 2026

Model names, prices and features below were checked against Anthropic’s documentation on 6 November 2026. Anthropic ships new models and features every few months: confirm current details in the Claude documentation and the Claude Code documentation before you commit to a design.
