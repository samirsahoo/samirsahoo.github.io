How to Answer AI System Design Interviews

A repeatable 8-step framework for AI and GenAI system design interviews — requirements, estimates, architecture, retrieval and models, agents and tools, evaluation, safety and governance, operations — with a 45-minute timeline, whiteboard template and practice questions.

Why a framework#

AI system design interviews test whether you can turn a vague product idea into an architecture that is useful, safe, measurable and affordable. Without a structure, candidates jump to “use a vector DB and GPT” and miss requirements, evaluation and risk — the parts interviewers weigh most for senior and architect roles.

The 8-step framework#

1. Clarify the problem (3–5 min)#

  • Who are the users? Internal or external? How many?
  • What tasks exactly? Answer questions, draft documents, take actions?
  • What does success look like? (Deflection rate, time saved, accuracy, CSAT.)
  • Is AI even the right tool, or would search/rules/forms work?

2. Requirements (5 min)#

Type Ask about
Functional Inputs/outputs, channels, languages, citations, actions, hand-off to humans
Non-functional Latency (TTFT, total), availability, freshness of knowledge, throughput
Quality Accuracy targets, acceptable error types, “I don’t know” behaviour
Security & privacy Data classification, permissions, PII, data residency, provider terms
Risk & compliance Regulatory tier (EU AI Act), human oversight, auditability
Cost Budget per request or per month

3. Estimates (3–5 min)#

Compute out loud:

  • Requests/day and peak per second.
  • Tokens per request (system + context + history + question; output).
  • Tokens/day → cost/day; peak tokens/minute vs provider limits.
  • Corpus size → number of chunks → vector storage.

See the worked numbers in the knowledge assistant case study and the cheat sheet.

4. High-level architecture (8–10 min)#

Draw from left to right, then trace one request end to end.

5. Deep dive on AI components (10 min)#

Pick the parts that matter most for this problem:

  • Knowledge: prompt-only vs RAG vs fine-tuning (decision guide); chunking, hybrid search, reranking, ACL filters; GraphRAG if multi-hop.
  • Model choice: tiering and routing; context window; reasoning model or not; hosting and data residency.
  • Prompting: system prompt structure, structured output, citations.
  • Agents: workflow vs agent; which tools; autonomy level per action; memory; human-in-the-loop.

6. Evaluation (3–5 min)#

  • Golden dataset: how built, how big, how maintained.
  • Retrieval metrics (recall@k, MRR) and generation metrics (faithfulness, relevance, correctness); for agents, task success and trajectory metrics.
  • CI gating; online sampling; user feedback; A/B tests on business metrics.

7. Safety, security, governance (3–5 min)#

  • Permissions at retrieval and in tools; identity propagation.
  • Prompt injection defences; tool gating; output sanitisation.
  • Human oversight and approval thresholds.
  • PII handling, logging policy, provider terms, regulatory classification.

8. Operations and trade-offs (3–5 min)#

  • Scaling: stateless services, index sharding, provider quotas.
  • Reliability: timeouts, retries, fallback models, degraded mode.
  • Cost levers: caching, routing, context trimming.
  • Rollout: shadow, canary, progressive autonomy.
  • Trade-offs you made and what you would do next.

Timeline for a 45-minute interview#

Minutes Step
0–5 Clarify problem and success
5–10 Requirements
10–14 Estimates
14–24 High-level architecture + request trace
24–34 Deep dive (RAG / agent / model)
34–38 Evaluation
38–42 Safety, security, governance
42–45 Trade-offs, scaling, next steps

What interviewers score#

Signal Strong answer Weak answer
Problem framing Asks about users, success metrics, risk Starts drawing immediately
Quantitative thinking Tokens, cost, peak TPM, storage No numbers
Simplicity Workflow before agent; pgvector before new DB Multi-agent everything
Retrieval depth Hybrid, rerank, chunking, ACL filters, freshness “Put it in a vector DB”
Evaluation Datasets, metrics, CI gates, online monitoring “We’ll test it”
Safety Injection, permissions, HITL, governance Not mentioned
Trade-offs Explicit, with alternatives One option presented as obvious

Practice questions#

  1. Design an internal knowledge assistant for 50,000 employees. (Worked answer)
  2. Design an AI customer-support agent that can issue refunds. (Worked answer)
  3. Design a system that extracts data from 1 million invoices a month into an ERP.
  4. Design a coding assistant for a 2,000-developer organisation with private repositories.
  5. Design an AI meeting-notes service with action items pushed into Jira.
  6. Design a contract-review assistant for a legal team, flagging risky clauses.
  7. Design an enterprise AI platform (gateway, RAG-as-a-service, guardrails) for 30 product teams.
  8. Design a fraud-investigation agent that queries transaction systems and drafts case reports.
  9. Design semantic search with Q&A over 10 years of support tickets in 8 languages.
  10. Design an AI assistant for relationship managers in a bank, compliant with the EU AI Act.

TipPractise aloud with a timer

Pick a question, set 45 minutes, talk through all 8 steps and draw the diagram. Then compare with the case studies and note what you missed.

Summary#

  • Clarify → requirements → estimates → architecture → AI deep dive → evaluation → safety/governance → operations and trade-offs.
  • Always compute tokens and cost, trace one request, and name evaluation metrics.
  • Prefer simple designs and justify every added component.
