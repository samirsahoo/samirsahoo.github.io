Managed Agent Platforms and Low-Code Builders

Cloud agent platforms — Amazon Bedrock AgentCore, Google Vertex AI Agent Engine, Azure AI Foundry Agent Service — what their building blocks do (runtime, memory, identity, tool gateway, browser, code interpreter, observability), how they compare with self-hosting, and where low-code agent builders fit.

Simple definition#

A managed agent platform runs agents for you. You bring agent code written with almost any framework; the platform provides an isolated, scalable runtime, managed memory, identity for agents, a tool gateway that turns APIs into MCP tools, sandboxed browser and code tools, and observability — the operational layer most teams would otherwise build on Kubernetes.

The building blocks#

Block What it does Why it matters
Runtime Serverless hosting for agent code; isolated session per user; long-running tasks No cross-session data leaks; scale to zero; hours-long runs
Memory Short-term session memory and long-term extracted memories No custom memory store to build
Identity Agent identities; OAuth flows; acting on behalf of users; token vault Least-privilege access to tools (agent identity)
Tool gateway Turns REST/OpenAPI, functions and SaaS into MCP tools with auth Governed tool access without writing MCP servers
Browser tool Managed, sandboxed browser for web tasks Computer-use without your own VMs
Code interpreter Sandboxed code execution Safe data analysis and calculations
Observability & evaluation Traces, metrics, online evaluations per session Operability and quality monitoring
Policy Rules on what agents and tools may do Central governance

The three hyperscaler offerings#

Amazon Bedrock AgentCore Vertex AI Agent Engine (Google) Azure AI Foundry Agent Service
Positioning Modular services to run any agent framework securely at scale Managed runtime for ADK and other frameworks Managed agents integrated with Foundry models and Microsoft 365
Typical framework Strands, LangGraph, CrewAI, others ADK, LangGraph, others Microsoft Agent Framework, others
Building blocks Runtime, Memory, Gateway, Identity, Browser, Code Interpreter, Observability, evaluations, policy Runtime, sessions, Memory Bank, evaluation, tracing (Cloud Trace), A2A Agents, threads, tools (incl. MCP, Logic Apps, OpenAPI), connected agents, tracing
Protocols MCP (gateway), A2A A2A native, MCP MCP, A2A
Fits AWS estates Google Cloud estates Azure / Microsoft 365 estates

AWS has positioned AgentCore as the platform for new agent builds, with the original Bedrock Agents continuing for existing deployments. Feature sets change frequently — compare current documentation.

Managed platform or self-hosted?#

Managed platform Self-hosted on Kubernetes
Time to production Fast Slower — build runtime, memory, identity, sandboxes
Session isolation Built in (for example micro-VM per session) You design it
Identity for agents Built in Integrate IdP, token exchange, vault
Sandboxed browser/code Built in Run your own sandboxes
Portability Tied to a cloud Portable
Cost model Pay per use Infrastructure + platform team
Control and customisation Limited to platform features Full

Low-code agent builders#

Business-facing builders let analysts compose agents visually with connectors:

Tool Notes
Microsoft Copilot Studio Agents for Microsoft 365 and Teams; connectors; governance via Power Platform
Salesforce Agentforce, ServiceNow, SAP Joule and similar Agents inside SaaS platforms, close to their data and workflows
n8n, Dify, Flowise, Langflow Open-source visual builders for flows, RAG and agents
Cloud agent builders Visual builders on top of the hyperscaler platforms

Use them for: departmental automations, prototypes, SaaS-centred workflows. Be careful with: version control, testing, evaluation, security review and sprawl — apply the same governance as for coded agents, and register every agent in the AI inventory.

Common mistakes#

Common mistakeAssuming the platform makes agents safe

The platform isolates sessions and manages identity; your tools still need authorisation, limits and approvals, and your agent still needs evaluation.

Common mistakeAgent sprawl from low-code tools

Hundreds of unregistered agents with broad connectors are a security and compliance risk. Require registration, ownership and review.

Review questions#

What does a managed agent platform provide? A session-isolated serverless runtime, memory, agent identity and token handling, a tool gateway exposing APIs as MCP tools, sandboxed browser and code tools, observability and evaluation, and policy controls.

When would you self-host agents instead? When you need multi-cloud portability, full control, or you already run a mature Kubernetes platform with AI gateway, identity and observability.

What are the risks of low-code agent builders? Weak version control and testing, inconsistent security review, broad connectors and agent sprawl — mitigated by registration, ownership, governance and evaluation.

Summary#

  • Managed platforms supply runtime, memory, identity, tool gateway, sandboxes and observability.
  • AgentCore, Vertex AI Agent Engine and Foundry Agent Service align with their clouds; all support MCP and A2A.
  • Self-host for portability and control; stay portable with MCP tools and Git-managed prompts and evals.
  • Govern low-code agents like any other agent.
