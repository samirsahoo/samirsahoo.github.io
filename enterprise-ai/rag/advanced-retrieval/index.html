Advanced RAG: Hybrid Search, Reranking, Query Transformation and Agentic RAG

The techniques that turn a prototype RAG into a production one: hybrid search with RRF, cross-encoder reranking, query rewriting, multi-query, HyDE, decomposition, contextual retrieval, context compression, routing, corrective and self-RAG, and agentic RAG.

Simple definition#

Advanced RAG adds steps before, during and after retrieval to find better context: fix the question (pre-retrieval), search in more than one way (retrieval), and filter and order what was found (post-retrieval). Agentic RAG goes further and lets an LLM decide when, where and how many times to search.

The advanced RAG pipeline#

Pre-retrieval: improve the query#

Technique What it does Example
Query rewriting / condensing Turns a follow-up into a standalone query using history “What about for contractors?” → “What is the parental leave policy for contractors in Germany?”
Multi-query expansion LLM generates 3–5 paraphrases; retrieve for each; merge Catches different wording in documents
HyDE (Hypothetical Document Embeddings) LLM writes a hypothetical answer; embed that and search Answers look more like documents than questions do
Query decomposition Splits multi-part questions into sub-questions “Compare the 2025 and 2026 travel policies” → two retrievals
Step-back prompting Ask a more general question first “Which leave types exist?” before a specific case
Translation Translate the query into the corpus language User asks in French, documents in English
Routing Choose the right index, source or tool HR question → HR index; “my open tickets” → ticket API
Metadata extraction Pull filters out of the question “in 2025 for Germany” → year=2025, country=DE

Hybrid search#

Dense (vector) search matches meaning; sparse (keyword/BM25) search matches exact terms. Enterprise questions need both: “error E-4031 when exporting invoices” has an exact code and a meaning.

Reciprocal Rank Fusion uses ranks, not raw scores, so it combines systems whose scores are on different scales. A document ranked 1st by BM25 and 3rd by vectors gets 1/61 + 1/63 ≈ 0.032, beating a document ranked 2nd by only one system (1/62 ≈ 0.016).

Alternatives: weighted score fusion (normalise then blend), or learned sparse models such as SPLADE that combine both ideas.

Reranking#

Retrieval models (bi-encoders) embed query and document separately — fast but approximate. A reranker (cross-encoder) reads the query and a candidate together and outputs a relevance score — slower but much more accurate.

  • Typical gain: one of the largest single quality improvements in RAG.
  • Options: hosted rerank APIs (Cohere, Voyage, cloud providers), open-weight cross-encoders (BGE reranker, ms-marco models), or an LLM as reranker (expensive).
  • Cost: adds ~50–300 ms; rerank only the top 20–100.
  • ColBERT (late interaction) sits between bi- and cross-encoders: token-level matching with pre-computed document vectors.

Contextual retrieval#

Chunks lose context when cut from their document. Contextual retrieval uses an LLM at ingestion time to write one or two sentences situating each chunk (“This chunk is from ACME’s Q2 2026 10-Q, discussing revenue in the EMEA segment…”) and prepends it before embedding and BM25 indexing. Combined with reranking, this was reported to cut retrieval failures by roughly two thirds. Prompt caching makes the ingestion cost modest.

Post-retrieval: make the context better#

  • Rerank and keep the top 3–8 chunks.
  • Deduplicate near-identical chunks (versions, copies).
  • Compress — extract only the relevant sentences, or summarise long chunks.
  • Order — most relevant first (and possibly last), to counter “lost in the middle”.
  • Expand — fetch parent sections or neighbouring chunks for context (small-to-big).
  • Prefer fresh — use dates and version metadata; tell the model to prefer the newest source.
  • Number sources for citations.

Self-correcting RAG#

Corrective RAG (CRAG) grades retrieved documents for relevance; if they are poor, it rewrites the query or falls back to another source (such as web or another index).

Self-RAG trains or prompts the model to decide whether retrieval is needed, to critique retrieved passages, and to check that its answer is supported.

Put a limit on loops (for example two rewrites) so cost and latency stay bounded.

Agentic RAG#

In agentic RAG, retrieval becomes a tool that an agent can call as often as it likes, alongside other tools.

Classic / advanced RAG Agentic RAG
Retrieval Once, fixed pipeline As many times as needed, chosen by the model
Sources Usually one index Many: indexes, SQL, APIs, web
Questions handled Single-hop Multi-hop, comparative, analytical
Latency / cost Predictable, low Higher, variable
Control High Lower — needs step limits and evaluation

Use agentic RAG when questions genuinely need multiple steps or sources; keep a fixed pipeline for simple Q&A, where it is cheaper, faster and easier to test.

What to add first#

Ranked by typical impact per effort:

  1. Better parsing and structure-aware chunking with heading context.
  2. Hybrid search (BM25 + vectors).
  3. Reranking.
  4. Metadata filters (date, product, region, ACL).
  5. Query rewriting for multi-turn chat.
  6. Contextual retrieval.
  7. Multi-query / HyDE / decomposition for hard questions.
  8. Agentic or graph-based retrieval for multi-hop questions.

Measure each change with RAG evaluation; not every technique helps every corpus.

Common mistakes#

Common mistakeAdding every technique at once

Each step adds latency, cost and failure modes. Add one, measure, keep it only if it helps.

Common mistakeRetrieving 50 chunks into the prompt instead of reranking

More context is not better context. It costs more and distracts the model. Retrieve wide, rerank, send few.

Review questions#

What is hybrid search and why use it? Running dense vector search and sparse keyword (BM25) search together and fusing results, typically with Reciprocal Rank Fusion. Vectors capture meaning; BM25 captures exact terms such as codes and names. Together they outperform either alone on enterprise text.

What does a reranker do and why not use it for the initial search? A cross-encoder that scores each query–document pair jointly, which is far more accurate than comparing separate embeddings. It is too slow to run over the whole corpus, so it reranks the top 20–100 candidates from fast retrieval.

Explain HyDE. Hypothetical Document Embeddings: the LLM writes a plausible answer to the query, and that text is embedded and used for search. Because it resembles the style of documents more than a short question does, it can retrieve better matches.

What is agentic RAG and when would you use it? An agent that uses retrieval as a tool, deciding which sources to query and iterating until it has enough evidence. Use it for multi-hop or analytical questions across multiple sources; avoid it for simple Q&A where a fixed pipeline is cheaper and more predictable.

How would you improve a RAG system with poor answer quality? Measure retrieval recall first. If retrieval is weak: fix parsing and chunking, add hybrid search, reranking, metadata filters, query rewriting, contextual retrieval. If retrieval is good but answers are poor: improve the prompt, context ordering and compression, model choice, and add faithfulness checks.

Summary#

  • Pre-retrieval fixes the question; retrieval searches in multiple ways; post-retrieval filters and orders.
  • Hybrid search + reranking is the highest-value upgrade for most systems.
  • Contextual retrieval restores context lost by chunking.
  • Corrective/self-RAG and agentic RAG add loops and tools for hard questions — with step limits.
  • Add techniques one at a time and measure.
