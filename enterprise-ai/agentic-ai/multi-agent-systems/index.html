Multi-Agent Systems

When and how to use multiple agents: supervisor, hierarchical, sequential pipeline, handoff/swarm, network, debate and blackboard topologies; communication and shared state; the A2A protocol; failure modes, cost and when a single agent is better.

Simple definition#

A multi-agent system splits work among several agents, each with its own instructions, tools and context, which coordinate to reach a goal. It is the AI equivalent of a team: a lead delegates to specialists.

Why use more than one agent?#

Reason Explanation
Separation of concerns Each agent has a focused prompt and a small tool set — easier to build, test and own
Context isolation A sub-agent explores in its own context window and returns only a short summary, keeping the lead’s context clean
Parallelism Independent research or analysis runs concurrently
Different models A frontier model plans; cheaper models execute
Organisational ownership Teams own “their” agent (HR agent, IT agent), like microservices
Security boundaries An agent that reads untrusted content has no access to sensitive tools

Trade-offThe cost

Multi-agent systems use several times more tokens than a single agent, add latency, and introduce coordination failures. Use them when the task is valuable and genuinely benefits from parallel or specialised work.

Topologies#

Supervisor (orchestrator)#

The most common production topology. Sub-agents are often exposed to the supervisor as tools (“agents as tools”).

Hierarchical#

Supervisors of supervisors, for large problem spaces. Each level keeps a manageable number of direct reports.

Sequential pipeline#

Fixed order, like an assembly line — really a prompt chain of agents. Predictable and easy to test.

Handoff (swarm)#

The active agent transfers the conversation (and control) to another agent. No central supervisor; good for customer-service flows where the user talks to one agent at a time.

Network / peer-to-peer#

Any agent can call any other. Flexible but hard to reason about, debug and bound — rarely the right choice in enterprises.

Debate and voting#

Several agents answer independently, critique each other, and a judge or majority decides. Improves accuracy on hard reasoning at high cost.

Blackboard (shared workspace)#

Agents read and write a shared state (the “blackboard”); a controller picks which agent acts next based on the state. Good for incremental problem-solving such as incident investigation.

Communication and state#

Approach How Notes
Agents as tools Supervisor calls sub-agent like a function; gets a result Simple, clear ownership of control
Message passing Agents send messages / tasks to each other Needs protocols, correlation IDs
Shared state Common state object or blackboard Needs a schema; risk of conflicting writes
Handoff Transfer conversation and control Pass a concise summary, not the full history

Design rules:

  • Give each agent a clear contract: input, expected output format, scope, tools.
  • Pass concise, structured summaries between agents — not entire transcripts.
  • Keep a single owner of the user conversation.
  • Propagate identity and permissions: a sub-agent acts with the original user’s rights, not more.
  • Use correlation IDs and distributed tracing across agents.

Agent-to-agent protocols#

A2A (Agent2Agent) is an open protocol, started by Google in 2025 and now under the Linux Foundation, for agents built by different teams or vendors to collaborate:

  • Agent Card — a JSON description of an agent’s skills, endpoint and auth.
  • Task — a unit of work with a lifecycle (submitted, working, input-required, completed, failed…).
  • Messages and artifacts — communication and outputs (text, files, structured data).
  • Runs over HTTP with JSON-RPC, streaming via server-sent events, and push notifications for long tasks.

MCP vs A2A: MCP connects an agent to tools and data; A2A connects agents to agents, treating the remote agent as an opaque peer that owns its own tools and reasoning.

Failure modes#

Research on multi-agent failures groups them into three families:

Family Examples
Specification problems Vague roles, overlapping responsibilities, unclear stop conditions
Inter-agent misalignment Agents ignore each other’s output, withhold information, duplicate work, talk in loops
Verification failures Nobody checks the final result; premature termination; errors amplified down the chain

Mitigations: explicit contracts and output schemas, a single coordinator, step and token budgets, a verification step with real checks, tracing of every agent hop, and evaluation of whole trajectories.

Common mistakes#

Common mistakeOrg-chart agents

Creating a “CEO agent”, “manager agent” and “analyst agent” because it mirrors a company. Agent boundaries should follow context, tools and security needs, not job titles.

Common mistakePassing full transcripts between agents

Context bloats, costs explode and agents get confused. Pass structured summaries.

Common mistakePrivilege escalation through delegation

A low-privilege agent asks a high-privilege agent to do something on its behalf. Propagate the original user’s identity and authorise at every hop.

Review questions#

When would you use a multi-agent architecture? When a task needs parallel exploration, distinct specialised tool sets, context isolation, different models for planning and execution, or separate team ownership — and the value justifies the extra cost and complexity. Otherwise a single agent is better.

Describe the supervisor pattern. A supervisor agent receives the task, decomposes it, delegates sub-tasks to specialised agents (often exposed as tools), collects their results and synthesises the final answer. It owns the user conversation and stop conditions.

What is the difference between handoff and supervisor? In handoff, control transfers from one peer agent to another, which then talks to the user directly. In supervisor, a central agent stays in control and calls sub-agents, which return results to it.

What is A2A and how does it relate to MCP? A2A is an open protocol for agents to discover each other through agent cards and delegate tasks with a defined lifecycle. MCP connects an agent to tools and data. They are complementary: an agent may use MCP for its tools and A2A to collaborate with other agents.

What are common failure modes of multi-agent systems? Poor specification (unclear roles and stop conditions), misalignment between agents (ignored outputs, loops, duplicated work) and missing verification. Mitigate with contracts, schemas, a coordinator, budgets, verification steps and tracing.

Review tipJustify every extra agent

For each agent in your design, state why it is separate: different tools, different security boundary, different model, parallelism, or different owner. If you cannot, merge it.

Summary#

  • Multi-agent systems split work across specialised agents: supervisor, hierarchical, pipeline, handoff, debate, blackboard.
  • Benefits: focus, context isolation, parallelism, ownership, security boundaries. Costs: tokens, latency, coordination failures.
  • Use clear contracts, summaries not transcripts, identity propagation, budgets and tracing.
  • A2A connects agents across teams and vendors; MCP connects agents to tools.
