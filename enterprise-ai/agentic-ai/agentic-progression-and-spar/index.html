From Generative to Agentic AI: Five Levels, SPAR and the Three Keystones

How agentic AI differs from generative AI, the six-step progression from manual work to fully autonomous agents (levels 0–5), the SPAR loop — sense, plan, act, reflect — the three keystones of action, reasoning and memory, LLMs vs large reasoning models, tool resilience by control and impact, and choosing between intelligent automation and agentic workflows.

Simple definition#

Generative AI produces content when asked. Agentic AI pursues a goal: it plans, uses tools, takes actions across systems, remembers, and improves from results — with as little human prompting as the task allows.

Agentic capability is not on or off. It is a progression, from rule-based automation to fully autonomous agents, and each step needs stronger sensing, planning, acting and reflecting.

Generative AI vs agentic AI#

Dimension Generative AI Agentic AI
Core capability Generate text, images, code from a prompt Plan, decide and execute multi-step work
Memory The current context only Persistent memory across sessions; plans adapt to it
Autonomy Waits for a human prompt each time Runs workflows with minimal human input
Integration Mostly standalone; occasional API use Deep integration with APIs, databases, business systems, sometimes physical systems
Learning Changes only when retrained Improves from interactions and feedback
Typical use Drafting, summarising, coding help, brainstorming Workflow automation, operations, assistants that complete tasks
Business effect Faster, better individual work Automated processes, reduced workload, scalable operations

Key conceptThe one idea to keep

Generative AI makes people faster at tasks; agentic AI takes over parts of processes. That shift moves the design questions from content quality to control, integration, accountability and failure recovery.

The progression: six levels from manual to autonomous#

A useful mental model borrows from self-driving cars: autonomy grows in levels, and most real systems today sit in the middle.

Level Car analogy What the system does Typical technology
0 — Manual No assistance People perform every step with basic digital tools Spreadsheets, email
1 — Rule-based automation Cruise control Follows fixed rules on structured inputs; logs errors, does not learn RPA, scripts, rule engines
2 — Intelligent process automation Lane keeping and adaptive speed, supervised Adds perception — reads documents, classifies, extracts — within a fixed process ML, NLP, computer vision, orchestration + RPA
3 — Agentic workflows Highway autopilot; human takes over in complex situations Generates content, reasons, plans and chains tools within a defined domain; limited memory LLMs, tool calling, memory stores
4 — Semi-autonomous agents Self-driving in specific conditions Sets its own sub-goals, recovers from errors, remembers across sessions and learns from experience Advanced reasoning models, long-term memory, real-time adaptation
5 — Fully autonomous agents Self-driving anywhere Handles any task, learns across domains, formulates goals with no human involvement Not yet achieved

Most production enterprise agents in 2026 sit at level 3, with selected level-4 behaviour in narrow domains (coding, IT operations, research). Level 5 remains an aspiration.

TipTwo different “levels” scales

This progression describes the capability of a system. The levels of autonomy in What is an agent? describe how much authority you grant it per action. A level-4-capable agent can — and in regulated work usually should — run with approval gates.

The SPAR loop: how an agent takes action#

People act by perceiving a situation, deciding what to do, doing it and learning from the result. Agents follow the same cycle, called SPAR:

How each capability grows across the levels:

Capability Level 1–2 Level 3 Level 4–5
Sense Predefined triggers, structured or semi-structured data Natural-language understanding, context awareness Multimodal perception; at level 5, full environmental awareness and goal formulation
Plan If-then rules, decision trees, basic ML decisions Reasoning with foundation models; orchestrating multi-step workflows Dynamic strategies, goal decomposition, original problem-solving
Act Deterministic actions, error handling Chaining tools, multi-step tasks Autonomous tool selection, error recovery
Reflect Logging, monitoring, no adaptation Short-term feedback, limited long-term memory Context across sessions, learning from experience, continuous self-improvement

SPAR is the business-friendly name for the agent loop (think → act → observe) with an explicit reflection and learning step.

The three keystones: action, reasoning, memory#

Agentic capability rests on three keystones. A weakness in any one limits the whole agent.

Keystone Question it answers Read more
Action Can it do things — use tools reliably, and cope when they fail? Tool calling, Agent planning and failure modes
Reasoning Can it think — plan, decompose, judge, recover? Workflow patterns
Memory Can it learn — remember context, facts, experience and feedback? Memory and state

Action: plans and tool resilience#

Ask a capable model to plan a task — “summarise a 30-page report and share it with the team, tracking who read it” — and it will produce a sensible sequence of tools with dependencies. Change a constraint (“cloud storage is unavailable”) and it re-plans around it. The planning is the easy part; the tools are where it breaks.

Assess each tool on two axes:

  • Control — how much the agent (or your team) controls the tool’s availability and behaviour. An in-process function is high-control; a third-party SaaS API is low-control.
  • Impact — how critical the tool is to achieving the goal.
Low impact High impact
High control Nice-to-have helpers (format converters). Little risk Core capabilities you own (summarisation, internal calculations). Invest in quality
Low control Peripheral external services. Fail gracefully Critical external dependencies (cloud storage, chat platforms, partner APIs). Need fallbacks, retries, circuit breakers, alternative tools and human escalation

TipDesign for the bottom-right quadrant

The tools that are both critical and outside your control are where agents fail in production. Give each one a fallback path and test the failure explicitly — see designing for recovery.

Reasoning: LLMs vs large reasoning models#

Large reasoning models (LRMs) are LLMs trained (often with reinforcement learning on verifiable problems) to reason step by step before answering, spending more compute at inference time — see test-time compute.

Standard LLM Large reasoning model
Strength Language tasks: translation, summarisation, dialogue, drafting Math, code, logic, multi-step planning and decisions
Reasoning Fast, pattern-based Slower, deliberate, more systematic
Cost and latency Lower Higher — many reasoning tokens
Best agent role Routing, extraction, conversation, simple tool steps Planning, complex decisions, verification, debugging

A constraint-heavy puzzle (a crossword, a schedule with many rules) shows the difference clearly: a fast model produces fluent but inconsistent answers; a reasoning model checks constraints and gets most of them right. In agents, use the fast model for the many simple steps and the reasoning model for planning and hard decisions — a routing decision.

Memory: three layers#

Layer What it holds Implementation Common pitfall Mitigation
1 · Short-term memory The current task and conversation The context window; attention over recent tokens Context overflow — losing critical details Summarise, trim, pin key facts
2 · Long-term memory Episodic (events and past interactions), semantic (facts and preferences), procedural (how-to knowledge, playbooks) Relational and document databases, vector stores, knowledge graphs Mis-categorised memories that cannot be retrieved Tagging, metadata, automated categorisation
3 · Feedback loop Outcomes and user feedback that change future behaviour Feedback logs in analytical stores; evaluation and tuning pipelines Ignoring or misreading feedback Clear success metrics; controlled updates to prompts, memory and models

The third layer is what lets an agent improve, and it is the one most often missing. See user feedback and memory and state.

Level 2 or level 3? Choosing the right automation#

Not every process needs an LLM agent. Intelligent process automation (level 2) is often the better answer.

Criterion Level 2 — intelligent automation Level 3 — agentic workflow
Task predictability Deterministic process with clear rules Needs context understanding and adaptive responses
Error sensitivity Must be 100% accurate and repeatable Tolerates some variability; probabilistic decisions acceptable with review
Input variability Standardised inputs Variable, unstructured inputs (emails, documents, conversations)
Best for High-volume, repetitive, fixed workflows Reasoning, judgement, natural language
Examples Data extraction to fixed fields, financial calculations, compliance checks, structured reporting Report writing, customer support, fraud investigation, trend analysis

Hybrid designs are common and often best: an agent handles the unstructured, judgement-heavy front of a process, then hands structured, validated data to deterministic automation for the regulated back end.

Common mistakes#

Common mistakeJumping to level 4

Designing for self-directed, self-learning agents when the process is not even documented. Most value today comes from well-bounded level-3 workflows.

Common mistakeIgnoring tool resilience

Testing only the happy path, then failing in production when a low-control, high-impact external tool times out. Map tools by control and impact and design fallbacks.

Common mistakeNo reflection layer

Building agents that act but never learn from outcomes. Without the feedback layer, the same mistakes repeat forever.

Review questions#

How does agentic AI differ from generative AI? Generative AI produces content in response to prompts; agentic AI pursues goals by planning, acting through tools and systems, remembering across sessions and improving from feedback, with minimal human prompting.

Describe the levels of the agentic AI progression. Level 0 manual; level 1 rule-based automation (RPA); level 2 intelligent process automation (ML and NLP in fixed processes); level 3 agentic workflows (LLMs plan and chain tools in a domain); level 4 semi-autonomous agents (adapt strategies, learn across sessions); level 5 fully autonomous agents (not yet achieved).

What is the SPAR framework? Sense, plan, act, reflect — the cycle an agent follows: gather inputs, reason and plan, execute through tools, then evaluate results and learn before the next cycle.

What are the three keystones of agentic AI? Action (reliable tool use and resilience), reasoning (planning, decomposition, judgement) and memory (short-term context, long-term episodic/semantic/procedural memory, and a feedback loop).

How do you assess tool risk for an agent? By control and impact. Tools that are high-impact but low-control — critical external services — need fallbacks, retries, circuit breakers, alternatives and escalation paths.

When would you choose intelligent automation over an agentic workflow? When the process is deterministic, inputs are standardised, and outputs must be exactly right every time. Use agents for variable, unstructured inputs and judgement-heavy steps.

Review tipPlace the system on the scale

State which level your design targets and why — and which actions still need human approval. It shows you separate capability from authority.

Summary#

  • Agentic AI pursues goals through planning, action, memory and learning; generative AI produces content on request.
  • Autonomy grows through six levels; most enterprise agents are level 3 today.
  • SPAR — sense, plan, act, reflect — is the agent’s operating cycle.
  • Action, reasoning and memory are the keystones; map tools by control and impact; use reasoning models where planning is hard.
  • Memory has three layers: short-term, long-term (episodic, semantic, procedural) and the feedback loop.
  • Choose level 2 automation for deterministic work, level 3 agents for judgement and unstructured inputs.
