What Is an AI Agent?

Agents explained simply: the agent loop, ReAct, workflows vs agents, the components of an agent (model, tools, memory, planning, guardrails), levels of autonomy, and when to use — and not use — agents.

Simple definition#

An AI agent is a system where an LLM decides what to do next, does it by calling tools, observes the result, and repeats until the goal is reached or it must stop.

A chatbot answers. An agent acts: it can look up an order, check a policy, issue a refund, and email the customer — choosing the steps itself.

From LLM to agent#

The most useful distinction:

Workflow Agent
Who decides the steps? Your code (predefined path) The LLM (dynamic)
Predictability High Lower
Testing Like normal software Needs scenario-based evaluation
Cost and latency Bounded, known Variable
Best for Well-understood, repeatable tasks Open-ended tasks where steps cannot be predicted

Key conceptStart with the simplest thing

Most enterprise “agent” use cases are better built as workflows with a few LLM steps. Use a true agent only when the path really cannot be known in advance.

The agent loop#

In code, the loop is short:

messages = [system_prompt, user_goal]
for step in 1..MAX_STEPS:
    response = llm(messages, tools)
    if response has no tool calls:
        return response.text                  # final answer
    for call in response.tool_calls:
        check permissions / ask for approval if risky
        result = execute(call.name, call.arguments)
        messages.append(tool_result(call.id, result))
return "Stopped: step limit reached"          # always bound the loop

ReAct: Reason + Act#

ReAct (Yao et al., 2022) interleaves reasoning and actions. The model writes a thought, chooses an action, reads the observation, and continues:

Thought: The customer asks why order 8812 is late. I need the order status.
Action: get_order(order_id="8812")
Observation: {"status": "held", "reason": "address_verification_failed"}
Thought: Address verification failed. I should check the address on file.
Action: get_customer_address(customer_id="C-301")
Observation: {"postcode": "SW1A 1AA", "verified": false}
Thought: I can explain and offer to update the address.
Final answer: Your order is on hold because we could not verify the delivery address...

Modern models do this natively through tool calling: the “Action” is a structured tool call, not text to parse.

Components of an agent#

Component Role Read more
Model Chooses actions, reasons over results Model selection
Instructions Define goal, scope, tone, rules, when to stop Prompt engineering
Tools The agent’s hands: read and change the world Tool calling, MCP
Memory Conversation state, user preferences, past cases Memory and state
Planning Break goals into steps; reflect and correct Workflow patterns
Guardrails Limit what it can do and spend Reliability, AI security

Levels of autonomy#

Level Description Example
0 — Assist Suggests; human does everything Draft an email reply
1 — Act with approval Proposes actions; human approves each “Refund €40? [Approve]”
2 — Act within limits Acts alone below thresholds; escalates above Auto-refund ≤ €50, else approval
3 — Autonomous with oversight Completes whole tasks; humans review samples and exceptions Overnight reconciliation agent
4 — Fully autonomous No routine human involvement Rare in regulated enterprises

Choose the level per action by impact and reversibility: reading is safe, writing needs limits, irreversible or high-value actions need human approval.

This table is about the authority you grant. For the matching scale of capability — from rule-based automation to fully autonomous agents — and the sense–plan–act–reflect cycle, see levels, SPAR and the three keystones.

When to use an agent#

Good fit: open-ended tasks with many possible paths (investigation, research, troubleshooting, coding), tasks spanning several systems, and tasks where a human currently follows judgment rather than a fixed procedure.

Poor fit: fixed procedures (use a workflow or plain code), strict latency or cost budgets, tasks needing guaranteed exact outcomes, and high-risk actions without a review step.

Common mistakes#

Common mistakeAn agent where a workflow would do

Letting the LLM decide steps that are always the same adds cost, latency and failure modes. If you can draw the flowchart, code it.

Common mistakeUnbounded loops

Without a maximum number of steps, tokens and time, an agent can loop on a failing tool and burn budget. Always bound it.

Common mistakeToo many tools

Giving one agent 80 tools confuses tool selection. Group tools, load them on demand, or split into specialised agents.

Review questions#

What is an AI agent? An LLM-driven system that pursues a goal by deciding on actions, executing them through tools, observing the results and iterating until done — with memory, instructions and guardrails around it.

What is the difference between a workflow and an agent? In a workflow, code defines the sequence of LLM calls and tools; in an agent, the LLM decides the sequence dynamically. Workflows are more predictable and cheaper; agents are more flexible for open-ended tasks.

Explain the ReAct pattern. The model alternates reasoning (“thought”), an action (tool call) and an observation (tool result) in a loop, so reasoning guides actions and results inform further reasoning, until it produces a final answer.

How do you decide how much autonomy to give an agent? By the impact and reversibility of each action: read-only actions can be autonomous; low-value reversible writes can be automatic within limits; high-value or irreversible actions require human approval. Combine with budgets, monitoring and audit logs.

When would you not use an agent? When the process is fixed and known, when latency or cost must be tightly bounded, when outcomes must be exact and auditable step by step, or when there is no safe way to limit its actions.

Review tipShow restraint

Reviewers are wary of designs that make everything an agent. Explicitly comparing a workflow and an agent for the problem, and choosing the simpler option where possible, is a strong signal.

Summary#

  • An agent loops: think → act through tools → observe → repeat, until done or stopped.
  • Workflows (code decides) vs agents (LLM decides): prefer workflows when the path is known.
  • Components: model, instructions, tools, memory, planning, guardrails.
  • Set autonomy per action by impact and reversibility; always bound steps, tokens and time.
