The Agent Protocol Stack: MCP, A2A, AG-UI, Agent Skills and AGENTS.md

How the open agent standards fit together in 2026 — MCP for tools and data, A2A for agent-to-agent delegation, AG-UI for agent-to-interface streaming, Agent Skills for packaged know-how, AGENTS.md for repository instructions — with an end-to-end flow, governance under the Agentic AI Foundation, and adoption guidance.

Simple definition#

Agents need to talk to three kinds of counterpart: tools and data, other agents, and people through a user interface. Since 2024 an open standard has emerged for each, plus two lightweight file conventions for giving agents know-how and instructions:

Standard Connects One-line purpose
MCP — Model Context Protocol Agent ↔ tools & data Discover and call tools, read resources, use prompts
A2A — Agent2Agent Agent ↔ agent Discover remote agents and delegate tasks with a lifecycle
AG-UI — Agent–User Interaction Agent ↔ user interface Stream typed events (text, tool calls, state) to front ends
Agent Skills (SKILL.md) Agent ↔ packaged know-how Folders of instructions, scripts and resources loaded on demand
AGENTS.md Agent ↔ repository A README for agents: build, test and style instructions

The stack in one picture#

One task across the stack#

  1. The UI sends the user’s request to the agent as an AG-UI run and listens to the event stream.
  2. The agent asks the LLM, which requests a tool; the agent calls it on an MCP server (tools/call) and streams TOOL_CALL_* events to the UI so the user sees progress.
  3. A policy check belongs to the finance team’s expense agent, so the agent delegates it as an A2A task and receives the result as an artifact.
  4. The final answer streams to the UI as TEXT_MESSAGE_* events; the UI renders options and an approval button.

MCP (recap)#

Agent-to-tool standard: hosts, clients and servers; tools, resources and prompts; stdio and Streamable HTTP; OAuth for remote servers. Full article: MCP.

A2A in more depth#

  • Agent Card — JSON published at a well-known URL describing the agent’s name, skills, endpoint, supported modalities and authentication.
  • Task — the unit of work with the lifecycle above; long tasks report progress by streaming (server-sent events) or push notifications to a webhook.
  • Messages and parts — text, files and structured data; results come back as artifacts.
  • Opaque agents — the client does not see the remote agent’s tools, prompts or memory: it is a black-box collaborator, which suits cross-team and cross-company work.
  • Security — standard HTTP auth schemes declared in the Agent Card (OAuth 2.0, OpenID Connect, API keys, mTLS); signed Agent Cards for authenticity.

A2A reached its 1.0 specification in 2026 and, like MCP, is governed under the Linux Foundation.

AG-UI#

AG-UI standardises the stream between an agent back end and an interactive front end, so any compliant UI can render any compliant agent:

Event family Examples UI behaviour
Lifecycle RUN_STARTED, RUN_FINISHED, RUN_ERROR Spinners, errors
Text TEXT_MESSAGE_START/CONTENT/END Streamed answer
Tool calls TOOL_CALL_START/ARGS/END Show “searching flights…”, render tool UIs
State STATE_SNAPSHOT, STATE_DELTA Shared state between agent and app (forms, canvases)
Human-in-the-loop Interrupt / resume patterns Approval buttons, edits

It is transport-agnostic (SSE, WebSockets, webhooks) and supported by several frameworks (LangGraph, CrewAI, Mastra, ADK, Microsoft Agent Framework, Pydantic AI and others). Related efforts define declarative, generated UI components that agents can send for rendering.

Agent Skills#

A skill is a folder containing a SKILL.md file — YAML front matter (name, description) plus instructions — and optional scripts, templates and reference files. The agent sees only each skill’s short description at start-up and loads the full skill when relevant (progressive disclosure), so hundreds of skills cost almost no context until used.

skills/
└── credit-memo/
    ├── SKILL.md            # name, description, step-by-step instructions
    ├── template.docx       # resources the instructions refer to
    └── scripts/
        └── ratios.py       # deterministic helpers the agent can run

Anthropic published Agent Skills as an open standard in December 2025; many agent products and coding tools now read the same format. Skills package procedural knowledge; MCP provides capabilities. They complement each other. See agent harnesses and skills.

AGENTS.md#

A Markdown file at the root of a repository with instructions for coding agents: how to build, test, lint, conventions and boundaries. Many coding agents read it automatically — a simple, tool-neutral way to give agents project context.

Governance of the standards#

In December 2025 the Linux Foundation launched the Agentic AI Foundation (AAIF) as a neutral home for open agent standards, starting with MCP, AGENTS.md and goose; other projects such as A2A have since been brought under Linux Foundation governance. Neutral governance reduces vendor-lock-in risk for enterprises adopting these protocols.

Adoption guidance#

Need Adopt
Agents use internal systems MCP servers per domain, behind an MCP gateway
Agents from different teams or vendors cooperate A2A with Agent Cards in a registry
Rich agent UIs across several agent back ends AG-UI (or your framework’s streaming protocol)
Reusable procedures and company know-how for agents Agent Skills in a governed repository
Coding agents in your repositories AGENTS.md in every repo

TipStart with MCP

Most enterprises get the fastest value from MCP: wrap high-value systems once, reuse them in every agent and AI assistant. Add A2A when you have several independently owned agents.

Security considerations#

  • MCP: tool poisoning, over-privileged servers, token passthrough (details).
  • A2A: spoofed or malicious remote agents, data leakage in task payloads, privilege escalation through delegation — use authenticated, signed Agent Cards, allow-lists and per-hop authorisation.
  • AG-UI: treat streamed content as untrusted in the browser; sanitise rendered output.
  • Skills: a skill can contain scripts and instructions — review, sign and version them like code; install only from trusted sources.

Review questions#

Which standard connects an agent to tools, to other agents and to a UI? MCP to tools and data, A2A to other agents, AG-UI to user interfaces.

What is an A2A Agent Card? A JSON document published by an agent describing its identity, skills, endpoint, capabilities and authentication requirements, used for discovery.

What is the difference between an Agent Skill and an MCP server? A skill packages know-how — instructions, templates and scripts loaded into context on demand. An MCP server exposes capabilities — tools and data reached through a protocol. Agents often use both.

Why does neutral governance of protocols matter? It reduces lock-in and increases trust that the standards will remain open, multi-vendor and stable.

Summary#

  • MCP (tools), A2A (agents), AG-UI (UI) form the protocol stack; Agent Skills and AGENTS.md package know-how and instructions.
  • A2A tasks have a lifecycle and opaque agents; AG-UI streams typed events; skills load on demand.
  • Standards are converging under Linux Foundation governance.
  • Secure every interface: tools, agents, UI and skills.
