Glossary

Short definitions of the enterprise AI and agentic AI terms used across the handbook, with links to the articles that explain them.

  • 6 min read
  • Reviewed November 1, 2026
  • #Reference

Definitions are deliberately short. Follow the links for the full explanation.

A#

A2A (Agent2Agent protocol)
An open protocol for agents to discover each other through agent cards and delegate tasks. See Multi-agent systems.
AG-UI (Agent–User Interaction protocol)
An open protocol streaming typed events between an agent and a user interface. See Agent protocol stack.
Advisor (Spring AI)
An interceptor around a ChatClient call, used for memory, RAG, logging, tool loops and custom concerns. See Spring AI fundamentals.
Agent
An LLM-driven system that loops — reason, act through tools, observe — until a goal is met. See What is an agent?
Agent framework
A library that runs the agent loop and adds state, tools, multi-agent coordination, guardrails and tracing. See Framework landscape.
Agent harness
Everything around the model that makes an agent reliable: loop, tools, permissions, context management, skills, checkpoints, verification. See Harnesses & skills.
Agent Skills
Folders with a SKILL.md and resources that agents load on demand. See Agent protocol stack.
AGENTS.md
A Markdown file in a repository with instructions for coding agents. See Agent protocol stack.
Agentic RAG
RAG where an agent decides when and where to retrieve, possibly several times. See Advanced retrieval.
AI gateway
The single controlled entry point to all models: auth, quotas, guardrails, routing, caching, logging, cost. See Enterprise AI stack.
ANN (approximate nearest neighbour)
Search that finds most of the closest vectors quickly without comparing all of them. See Vector databases.
Attention
The transformer mechanism by which each token weighs and uses information from other tokens. See How LLMs work.
AgentOps
Operating agents like production services: SLOs, monitoring, incidents, cost and continuous evaluation. See Agentic AI strategy.
Air-gapped deployment
Running models with no network path to the outside; updates imported offline. See On-prem & hybrid.

B–C#

BM25
A classic keyword relevance ranking function used in sparse/keyword search. See Advanced retrieval.
Chunking
Splitting documents into passages for retrieval. See Chunking and embeddings.
Computer-use agent
An agent that operates graphical interfaces from screenshots with clicks and keystrokes. See Computer-use agents.
Context engineering
Deciding everything that goes into the context window on each call. See Prompt and context engineering.
Context window
The maximum tokens (input + output) a model processes per call. See How LLMs work.
Contextual retrieval
Prepending an LLM-written situating sentence to each chunk before indexing. See Advanced retrieval.
Cross-encoder / reranker
A model that scores a query and a document together for precise relevance. See Advanced retrieval.
Data-classification routing
An AI gateway choosing the allowed model deployment by the highest data class in the assembled prompt. See On-prem & hybrid.

D–E#

Distillation
Training a small model on a large model’s outputs. See Prompting vs RAG vs fine-tuning.
Embedding
A vector representing the meaning of text. See Chunking and embeddings.
EU AI Act
The EU regulation classifying AI systems by risk tier with matching obligations. See AI governance.
Evaluator–optimizer
A loop where one LLM generates and another critiques until criteria are met. See Workflow patterns.
Embabel
A JVM agent framework on Spring AI that plans typed actions toward goals with GOAP. See JVM frameworks.
Excessive agency
An LLM system with more tools, permissions or autonomy than it needs. See AI security.

F–H#

Faithfulness (groundedness)
Whether every claim in an answer is supported by the retrieved context. See RAG evaluation.
Fine-tuning
Further training of a model’s weights on your examples. See Prompting vs RAG vs fine-tuning.
GenAI adoption maturity
Stages from explore and experiment to formalise, scale and transform. See GenAI adoption strategy.
GOAP (goal-oriented action planning)
A planning algorithm from game AI that chains actions by preconditions and effects to reach a goal. See JVM frameworks.
Golden dataset
A versioned set of test cases with expected answers used for evaluation. See RAG evaluation.
GraphRAG
RAG over a knowledge graph of entities, relationships and community summaries. See GraphRAG.
Guardrails
Checks on inputs, actions and outputs that keep an AI system within policy. See Agent reliability.
Hallucination
Fluent but unsupported or false model output. See How LLMs work.
HNSW
A multi-layer graph index for fast approximate vector search. See Vector databases.
Human-in-the-loop (HITL)
Pausing an AI process for human approval, correction or input. See Workflow patterns.
Hybrid AI deployment
Some workloads on your own infrastructure, others on cloud models, under one control plane. See On-prem & hybrid.
Hybrid search
Combining vector and keyword search, usually fused with RRF. See Advanced retrieval.
HyDE
Searching with the embedding of an LLM-generated hypothetical answer. See Advanced retrieval.

K–L#

KV cache
Stored attention keys and values that speed up generation. See Inference.
Lethal trifecta
Private data + untrusted content + external communication in one agent. See AI security.
LangGraph
A graph runtime for agents with durable checkpoints and interrupts. See Python & TypeScript frameworks.
LLM-as-a-judge
Using an LLM with a rubric to grade outputs. See RAG evaluation.
LLMOps
Practices for operating LLM applications. See LLMOps.
LoRA
Parameter-efficient fine-tuning with small low-rank adapters. See Prompting vs RAG vs fine-tuning.

M–N#

MCP (Model Context Protocol)
An open protocol for AI applications to use tools, resources and prompts from servers. See MCP.
Managed agent platform
A cloud service that runs agents with session isolation, memory, identity, tool gateways and observability. See Managed platforms.
Mixture of Experts (MoE)
A model architecture that routes each token to a few expert sub-networks. See How LLMs work.
Model routing
Sending each request to the cheapest capable model. See Model selection.
MRR / nDCG
Retrieval ranking metrics. See RAG evaluation.
Model risk management (MRM)
Banking discipline (SR 11-7, PRA SS1/23) for inventorying, validating and monitoring models, now applied to LLMs. See Hybrid AI in financial services.
Model-weight ownership
Who holds a model’s weights, deciding whether you can pin, move and keep it. See Hybrid AI in financial services.
NIST AI RMF
A risk-management framework with Govern, Map, Measure and Manage functions. See AI governance.

O–R#

Orchestrator–workers
A central LLM dynamically delegating sub-tasks to workers. See Workflow patterns.
OWASP Top 10 for LLM Applications
The ten most critical security risks for LLM apps. See AI security.
Prompt caching
Reusing computation for a repeated prompt prefix. See Inference.
Prompt injection
Input that makes a model follow attacker instructions. See AI security.
Quantization
Storing weights or vectors at lower precision to save memory. See Inference.
RAG (retrieval-augmented generation)
Retrieving relevant passages and generating an answer grounded in them. See RAG fundamentals.
ReAct
An agent pattern interleaving reasoning, actions and observations. See What is an agent?
Reasoning model
A model trained to think step by step before answering. See How LLMs work.
RRF (reciprocal rank fusion)
Merging ranked lists by summing 1/(k + rank). See Advanced retrieval.

S–Z#

Shadow AI
Staff using unapproved AI tools, often with company data. See GenAI adoption strategy.
Sovereign cloud
Cloud operated under local jurisdiction by a local entity and staff. See On-prem & hybrid.
Structured output
Model output constrained to a schema and parsed into types. See Prompt engineering.
Temperature
A sampling setting controlling randomness. See How LLMs work.
Token
The sub-word unit models read and write. See How LLMs work.
Token exchange (on-behalf-of)
An OAuth flow giving an agent a short-lived, scoped token to act for a user. See Agent identity.
Tool calling (function calling)
The model requesting your application to run a function. See Tool calling.
ToolContext (Spring AI)
Data passed to tools without exposing it to the model. See Spring AI tools.
Vector database
A store optimised for nearest-neighbour search over embeddings with filters. See Vector databases.
Zero data retention (ZDR)
Provider terms under which prompts and outputs are not stored after processing. See On-prem & hybrid.
