Platform Review Checklist

A repeatable checklist for reviewing Kubernetes and platform designs: nine review areas with questions and red flags, a 0–3 scoring rubric and a one-page review template.

How to use it#

Use this checklist to review your own design before building, or a team’s design at an architecture board or production-readiness review. Score each area 0–3 and record evidence.

1. Goals and SLOs#

  • Business goals and users defined? SLOs, RTO and RPO per service tier?
  • Red flags: “five nines” for everything; no owner per service.

2. Cluster topology#

  • Managed or self-managed — and why? How many clusters, by environment/region/tenancy? Zones?
  • Upgrade cadence and process? Clusters reproducible from code?
  • Red flags: hand-built snowflake clusters; versions more than two minors behind; single-zone production.

3. Workloads#

  • Requests/limits, probes, PDBs, topology spread, autoscaling for every production workload?
  • Stateful services on managed databases or mature operators? Backups tested?
  • Red flags: BestEffort Pods in prod; liveness probes that check dependencies; databases without tested restore.

4. Networking#

  • Gateway API (not ingress-nginx); TLS everywhere; DNS automation?
  • Default-deny NetworkPolicies; egress control; IP plan for growth?
  • Service mesh justified?
  • Red flags: one LoadBalancer per app; flat network; retired ingress controller.

5. Security#

  • OIDC for humans; least-privilege RBAC; no cluster-admin for CI or apps?
  • Pod Security restricted; policy as code enforced; secrets in an external store; workload identity?
  • Signed images verified at admission; SBOMs; runtime detection; audit logs?
  • Red flags: secrets in Git; :latest images; privileged Pods; shared admin kubeconfigs.

6. Delivery#

  • Build once, promote by digest; DevSecOps scans; GitOps pull model?
  • Progressive delivery with automated analysis and rollback? Database migration strategy?
  • Change management automated with evidence; release orchestration where needed?
  • Red flags: CI with production credentials; manual helm upgrade in prod; per-environment rebuilds.

7. Platform and developer experience#

  • Golden paths for common tasks; catalog with owners; self-service infrastructure APIs?
  • Platform run as a product with users, roadmap, metrics and SLOs?
  • Red flags: ticket-driven provisioning; portal without automation; mandated tools nobody likes.

8. Observability and resilience#

  • OpenTelemetry instrumentation; metrics, logs, traces correlated; SLO burn-rate alerts; runbooks?
  • Timeouts, retries (one layer), circuit breakers; DR strategy per tier; drills; chaos experiments?
  • Red flags: alerts on CPU only; no tracing; untested DR.

9. Cost and operations#

  • Cost allocation by team (labels enforced); showback; budgets and anomaly alerts?
  • Rightsizing, autoscaling, spot, commitments, non-prod schedules?
  • On-call, incident process, postmortems, platform team capacity?
  • Red flags: no cost visibility; requests far above usage; heroic on-call.

Scoring rubric#

Score Meaning
0 Missing
1 Mentioned, not designed
2 Designed with some gaps
3 Designed and evidenced (tests, numbers, prototypes, drills)

Ready for production when no area is 0, security and resilience score 3 for Tier 0/1 services, and all gaps have owners and dates.

Summary#

  • Review nine areas from goals to cost; look for red flags; score with evidence.
  • Approve with conditions and owners; re-review after major changes.
