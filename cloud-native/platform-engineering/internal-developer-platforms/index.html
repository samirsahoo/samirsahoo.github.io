Internal Developer Platforms: Architecture and Tools

IDP reference architecture planes (developer control plane, integration and delivery, resources, observability, security), the developer portal with Backstage (catalog, software templates, TechDocs, scorecards), platform orchestrators and infrastructure APIs (Crossplane, kro, Terraform), golden-path flows, build vs buy, and CNOE reference stacks.

Simple definition#

An internal developer platform (IDP) is the sum of tools, APIs, templates and automation that a platform team integrates into self-service golden paths. A developer portal (such as Backstage) is the front door to the IDP — but the portal is not the platform; the automation behind it is.

Reference architecture#

Plane Purpose Typical tools
Developer control plane Where developers interact: portal, CLI, IDE, templates, docs Backstage / Red Hat Developer Hub, Port, Cortex; IDE plug-ins
Integration & delivery Build, store and deliver artifacts GitHub Actions, GitLab, Tekton; OCI registries; Argo CD, Flux; Argo Rollouts
Resource plane Run workloads and provision infrastructure Kubernetes, cloud services; Crossplane, kro, Terraform/OpenTofu modules; platform orchestrators
Observability plane Telemetry and SLOs OpenTelemetry, Prometheus, Grafana, tracing backends
Security plane Identity, secrets, policy, supply chain Vault, External Secrets, Kyverno/OPA, Sigstore, scanners

The developer portal: Backstage#

Backstage, created at Spotify and now a CNCF project, is the most widely used portal framework.

# catalog-info.yaml in every repository
apiVersion: backstage.io/v1alpha1
kind: Component
metadata:
  name: orders
  description: Order management service
  annotations:
    argocd/app-name: orders-prod
    backstage.io/techdocs-ref: dir:.
spec:
  type: service
  lifecycle: production
  owner: team-shop
  system: checkout
  providesApis: [orders-api]
  dependsOn: [resource:orders-db]
  • Software catalog — ownership, dependencies and metadata for every service, API and resource: the backbone for incident response, security and cost.
  • Software templates — golden paths that create repos, CI, manifests and catalog entries.
  • TechDocs — Markdown docs next to code, rendered in the portal.
  • Plugins — show Kubernetes status, Argo CD sync, pipelines, alerts and cost per service.
  • Options: self-host Backstage (needs a team to maintain), Red Hat Developer Hub (supported Backstage), managed Backstage (Roadie), or alternative portals (Port, Cortex, OpsLevel).

Infrastructure as APIs#

Developers should request capabilities (“a Postgres database for orders, prod size”) rather than raw cloud resources.

Tool Approach
Crossplane Kubernetes control plane for infrastructure; Composite Resource Definitions + Compositions; providers for every cloud
kro (Kube Resource Orchestrator) Define custom APIs that group Kubernetes resources (including cloud controller resources) into a graph
Terraform / OpenTofu modules Mature IaC; exposed via templates, pipelines or operators
Platform orchestrators (for example Humanitec) Generate environment-specific config from a workload spec (Score) and rules

Golden path in action#

The developer platform case study shows the full flow: a developer picks a template, the platform creates the repository and pipeline, provisions a namespace and database through claims, and Argo CD deploys the first version — in minutes, without tickets.

Reference stacks#

  • CNOE (Cloud Native Operational Excellence) — an industry initiative publishing open-source reference implementations (Backstage + Argo CD + Crossplane + Argo Workflows + Keycloak and more).
  • Cloud provider platforms — opinionated combinations on EKS, AKS, GKE.
  • OpenShift — integrated delivery, GitOps and Developer Hub (OpenShift).

Build, buy or assemble?#

Option Pros Cons
Assemble open source (Backstage, Argo CD, Crossplane) Flexible, no licence Needs a strong platform team
Commercial portals / orchestrators Faster value, support Cost, vendor fit
Integrated platform (OpenShift + Developer Hub) One vendor, integrated Less choice, licence

Most enterprises assemble around a few strategic open-source components and buy where differentiation is low.

Common mistakes#

Common mistakePortal first, platform later

A beautiful catalog with no automation behind it is a documentation site. Build the golden paths and APIs; the portal surfaces them.

Common mistakeExposing raw cloud resources

Developers then need cloud expertise again. Expose capabilities with sensible defaults and policies.

Common mistakeAn incomplete catalog

If ownership data is missing, incident response and cost allocation fail. Make catalog registration part of every template.

Quick check#

What is the difference between an IDP and a developer portal? The IDP is the platform — tools, APIs, automation and golden paths; the portal is its user interface.

Name the five planes of an IDP reference architecture. Developer control plane, integration and delivery, resource, observability and security planes.

What are Backstage’s core features? Software catalog, software templates (scaffolder), TechDocs and a plugin ecosystem (plus scorecards via plugins).

What does Crossplane do? Turns Kubernetes into a control plane for infrastructure: platform teams define composite APIs and compositions; developers create claims that provision cloud resources.

Why expose capabilities instead of raw resources? To hide complexity, apply secure defaults and policies, and reduce developer cognitive load.

Summary#

  • An IDP integrates delivery, infrastructure, security and observability into golden paths; the portal is its face.
  • Backstage provides catalog, templates, docs and plugins.
  • Crossplane, kro and IaC modules turn infrastructure into self-service APIs.
  • Assemble strategically; keep the catalog complete; build automation before UI.
