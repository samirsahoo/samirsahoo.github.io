Release Orchestration with Digital.ai Release and Deploy

Why large enterprises add release orchestration on top of CI/CD and GitOps, and how Digital.ai Release and Digital.ai Deploy work: templates, phases, tasks and gates, approvals and compliance evidence, Argo CD, Argo Rollouts, Flux and Tekton integrations, Live Deployments, deployment models, and alternatives.

Simple definition#

Release orchestration coordinates everything that has to happen for a release across many teams, tools and environments: builds, deployments, tests, security checks, approvals, change tickets, communications and evidence for auditors. CI/CD and GitOps automate a pipeline; release orchestration automates the release process around many pipelines.

Digital.ai Release (formerly XebiaLabs XL Release) is a release orchestration platform; Digital.ai Deploy (formerly XL Deploy) is a model-driven deployment automation tool. They are part of the wider Digital.ai platform, which also includes agile planning, continuous testing and application security products.

Why enterprises add an orchestration layer#

Challenge in large organisations What orchestration adds
A release spans 20 services, a mainframe and a database change One release plan coordinating all of them
Many tools: Jenkins, GitHub Actions, Argo CD, ServiceNow, Jira, test tools Integrations and a single view
Regulated change management (CAB, segregation of duties) Automated approvals, gates, audit trail, evidence
Different deployment targets: Kubernetes, VMs, cloud, packaged apps Model-driven deployment and plug-ins
Visibility for management Dashboards, release calendars, risk scores, DORA-style metrics

Release orchestration in the delivery flow#

  1. CI builds, tests, scans and signs the artifact once.
  2. The release orchestrator runs the release template: deploys to test (through Argo CD or Deploy), collects test and security results, evaluates quality gates and a risk score.
  3. Change approval is automatic for low-risk changes or routed to a CAB/ServiceNow change for high-risk ones.
  4. Production deployment runs through GitOps and progressive delivery (Argo Rollouts canary).
  5. Analysis promotes or triggers an automatic rollback; every step is recorded for audit.

Core concepts in Digital.ai Release#

Concept Meaning
Template A reusable release blueprint (for example “Monthly payments platform release”)
Release A running instance of a template, with its own variables and timeline
Phase A stage of the release: Build, Test, Approve, Deploy to production, Verify
Task A unit of work: automated (call Jenkins, sync Argo CD, create ServiceNow change, run tests) or manual (sign-off)
Gate A checkpoint that blocks progress until conditions are met (tests passed, approvals given, dependencies released)
Variables Values passed between tasks (version, image digest, change ticket number)
Folders and teams Organise templates and permissions per business unit
Triggers Start releases from events (new artifact, Git tag, deployment event)
Dashboards, Release Calendar, Risk profile Portfolio view, blackout windows, risk scoring

Cloud native integrations#

Recent Digital.ai Release versions (26.x, 2026) emphasise Kubernetes and GitOps:

  • Argo CD plugin — sync, wait for health, roll back, terminate a running operation, and manage ignoreDifferences rules from release tasks; onboarding workflows to create Argo CD Applications.
  • Argo Rollouts plugin — drive blue-green and canary rollouts and promotions as release tasks.
  • Flux CD and Tekton container-based plugins.
  • Live Deployments — a single view of what is deployed where, whether deployed by Release, Deploy, Argo CD or Flux; deployment events can trigger releases.
  • Digital.ai Deploy GitOps — exchange infrastructure and environment configuration items with Git as YAML.
  • Integrations with Jenkins, GitHub, GitLab, Azure DevOps, Jira, ServiceNow, test and security tools; a Release MCP server (beta) for AI assistants.

Digital.ai Deploy (model-driven deployment)#

Deploy describes what to deploy (a versioned deployment package of artifacts and resources) and where (environments of infrastructure items); it calculates the steps (create, modify, destroy) and runs them with rollback. It is valuable for non-Kubernetes targets — application servers, VMs, databases, mainframe-adjacent systems — which are still common in banks and insurers. For Kubernetes, GitOps tools usually perform the deployment, orchestrated by Release.

Deployment models#

  • SaaS or self-hosted (including on Kubernetes via an operator).
  • Remote runners execute container-based tasks close to target environments.

When to use release orchestration#

Use it when: many teams release interdependent changes; regulated change management requires evidence and approvals; you deploy to a mix of Kubernetes and legacy targets; leadership needs portfolio-level release visibility.

You may not need it when: teams deploy independent microservices continuously with GitOps and automated gates, and audit needs are met by Git history and pipeline evidence.

Alternatives and complements#

Tool Notes
Kargo Open-source, GitOps-native multi-stage promotion
Harness, Octopus Deploy, CloudBees Commercial CD/release platforms
Spinnaker Open-source multi-cloud CD (heavier to operate)
GitLab / GitHub environments + deployment protection rules Built-in approvals and environment gates
ServiceNow DevOps Change Change automation tied to pipelines

Common mistakes#

Common mistakeOrchestration that re-implements CI

The orchestrator should call CI and GitOps, not replace them. Keep build logic in CI and deployment in GitOps.

Common mistakeEvery release through a manual CAB

Use risk scoring and automated evidence so low-risk changes are approved automatically; reserve CAB for high-risk ones.

Quick check#

What does release orchestration add to CI/CD? Coordination of multi-team, multi-tool releases with phases, gates, approvals, change management integration, audit evidence and portfolio visibility.

What is the difference between Digital.ai Release and Digital.ai Deploy? Release orchestrates the end-to-end release process across tools and teams; Deploy automates the deployment itself using a model of packages and environments, especially for non-Kubernetes targets.

How does Digital.ai Release work with GitOps? Through plugins: it drives Argo CD syncs, rollbacks and operations, Argo Rollouts promotions and Flux workflows as tasks, and shows live deployment state from those tools.

What is a gate in a release template? A checkpoint that blocks the release until conditions — test results, approvals, dependencies — are satisfied.

Summary#

  • Release orchestration coordinates complex enterprise releases above CI/CD and GitOps.
  • Digital.ai Release: templates, phases, tasks, gates, approvals, dashboards, audit.
  • Digital.ai Deploy: model-driven deployments, valuable for legacy targets.
  • 2026 versions integrate deeply with Argo CD, Argo Rollouts, Flux and Tekton.
