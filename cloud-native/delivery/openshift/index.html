Red Hat OpenShift

What OpenShift adds to Kubernetes: integrated platform components, Routes, Security Context Constraints, Operators and OperatorHub, builds and S2I, OpenShift Pipelines (Tekton), OpenShift GitOps (Argo CD), Service Mesh, Virtualization, Developer Hub, deployment options (ROSA, ARO, on-premises) and how it compares with upstream Kubernetes.

Simple definition#

Red Hat OpenShift is an enterprise Kubernetes platform: certified Kubernetes plus an integrated, supported set of components — operating system, networking, ingress, registry, monitoring, logging, security, CI/CD, GitOps, service mesh, virtualization and a developer portal — installed and upgraded as one product.

OpenShift vs upstream Kubernetes#

Area Upstream Kubernetes OpenShift
Node OS Your choice RHCOS, managed via Machine Config Operator
Runtime containerd/CRI-O CRI-O
Ingress Choose a controller Routes (HAProxy router) + Ingress + Gateway API support
Security defaults Pod Security Admission Security Context Constraints (SCCs) + PSA; containers run as random non-root UIDs
Extensions Install operators yourself OperatorHub + Operator Lifecycle Manager (OLM)
Builds External CI BuildConfigs, Source-to-Image (S2I), Shipwright
CI/CD Choose tools OpenShift Pipelines (Tekton), OpenShift GitOps (Argo CD)
Upgrades Component by component Over-the-air cluster upgrades via the Cluster Version Operator
Support Community/vendor mix Single vendor for the whole stack

Key OpenShift concepts#

  • Projects — namespaces with extra annotations and default RBAC for teams.
  • Routes — OpenShift’s original way to expose HTTP(S) services with edge, passthrough or re-encrypt TLS.
  • SCCs — cluster-level policies controlling privileges; the default restricted-v2 blocks root and privilege escalation. Many public images that assume root need small changes to run.
  • Operators everywhere — the platform itself is managed by operators, so it self-heals and upgrades consistently.
  • Machine API / MachineSets — declarative node provisioning and autoscaling on supported infrastructure.

Developer and delivery features#

  • OpenShift Pipelines — Tekton-based, Kubernetes-native pipelines (Tasks and Pipelines as CRDs), plus Pipelines-as-Code.
  • OpenShift GitOps — supported Argo CD; recent releases add an Argo CD agent model for pull-based multi-cluster delivery.
  • Red Hat Developer Hub — a supported Backstage distribution for an internal developer portal.
  • OpenShift Service Mesh (Istio-based) and Serverless (Knative).
  • OpenShift Virtualization (KubeVirt) runs VMs next to containers — a common path for migrating VMware estates; 4.21 added live cross-cluster VM migration.
  • OpenShift AI for model serving and MLOps; recent releases support Dynamic Resource Allocation for GPUs.

Deployment options#

Option Notes
OpenShift Container Platform Self-managed on bare metal, VMware, OpenStack or cloud
ROSA (Red Hat OpenShift Service on AWS), ARO (Azure Red Hat OpenShift), OpenShift Dedicated Managed by Red Hat and the cloud provider
Single-node / compact clusters Edge and small sites
Advanced Cluster Management (ACM) Multi-cluster governance, placement and policy
Advanced Cluster Security (ACS) Image scanning, runtime detection, compliance (StackRox)

When to choose OpenShift#

Good fit: regulated enterprises wanting one supported platform; hybrid or on-premises estates; VMware migrations; teams that value integrated security defaults and over-the-air upgrades.

Consider alternatives when: you are cloud-only and comfortable assembling managed Kubernetes with your chosen add-ons, or licence cost outweighs the integration value.

Common mistakes#

Common mistakeRunning images that require root

They fail under the restricted SCC. Build images that run as arbitrary non-root users (group 0 writable directories) rather than loosening SCCs.

Common mistakeUsing OpenShift like plain Kubernetes and ignoring its operators

Hand-installing alternatives to platform components increases upgrade friction. Use the supported operators unless there is a clear reason.

Quick check#

What does OpenShift add to Kubernetes? An integrated, supported stack: RHCOS, CRI-O, OVN networking, Routes, registry, monitoring, logging, SCC security, OperatorHub/OLM, Pipelines, GitOps, Service Mesh, Virtualization, Developer Hub and managed over-the-air upgrades.

What is an SCC? A Security Context Constraint — OpenShift’s policy controlling what privileges Pods may use; the default restricted profile runs containers as random non-root UIDs.

What are OpenShift Pipelines and GitOps based on? Tekton and Argo CD respectively.

What is ROSA? Red Hat OpenShift Service on AWS — managed OpenShift jointly operated by Red Hat and AWS.

Why do teams run VMs on OpenShift? OpenShift Virtualization (KubeVirt) lets them run and migrate VMs alongside containers on one platform, for example when moving off VMware.

Summary#

  • OpenShift is Kubernetes plus a supported, integrated platform managed by operators.
  • Key differences: RHCOS, SCCs, Routes, OLM, built-in CI/CD (Tekton) and GitOps (Argo CD).
  • Available self-managed or as ROSA/ARO; ACM and ACS for fleets and security.
  • Strong fit for regulated, hybrid and VM-migration scenarios.
